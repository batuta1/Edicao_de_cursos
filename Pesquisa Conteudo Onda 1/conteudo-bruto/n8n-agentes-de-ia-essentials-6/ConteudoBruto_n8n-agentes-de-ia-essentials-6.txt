3. PRIMEIROS PASSOS (passo a passo oficial)
   Fluxo mínimo do exercício, preservando os nomes da ajuda em inglês:
   1. Crie um workflow: Overview > Create Workflow (interface a conferir).
   2. Adicione “Chat Trigger”/“When chat message received”. Durante a montagem deixe “Make Chat Publicly Available” desligado; depois escolha “Hosted Chat” ou “Embedded Chat” (ajuda en) [7].
   3. Adicione “AI Agent”. Conecte um Chat Model e pelo menos uma Tool; o nó exige ao menos uma ferramenta (ajuda en) [5].
   4. No AI Agent, em “Prompt”, use “Take from previous node automatically”; a entrada esperada é chatInput (ajuda en) [6].
   5. Em “Options > System Message”, descreva objetivo, fontes autorizadas, quando usar cada ferramenta e o que é proibido (ajuda en) [6].
   6. Mantenha “Max Iterations” em 10 no primeiro teste; esse é o padrão oficial (ajuda en) [6].
   7. Conecte “Simple Memory”. Defina “Session Key” e “Context Window Length” (ajuda en) [8]. Para produção/queue mode, prefira Postgres/Redis; Simple Memory não funciona de modo confiável em queue mode [8].
   8. Para a fonte, carregue um documento com “Default Data Loader”, um text splitter, um Embeddings node e um Vector Store em “Insert Documents”; depois conecte o vector store ao agente como Tool (ajuda en) [9].
   9. Para a ação, conecte uma ferramenta de aplicativo, por exemplo Google Sheets Tool com operação de leitura ou gravação, usando credencial criada no gerenciador.
   10. Para ação sensível, abra o conector “Tools” do AI Agent > seção “Human review” > escolha Chat, Slack, Telegram, Teams, Gmail ou WhatsApp e conecte a ferramenta que precisa de aprovação (ajuda en) [16].
   11. Execute manualmente, envie uma pergunta, confirme a consulta à fonte e verifique a ação no aplicativo de destino.
   12. Em Overview > Executions, abra a execução e confira os nós, entradas, saídas e chamadas de ferramenta (ajuda en) [38].
   13. Só depois ative “Make Chat Publicly Available” e configure Authentication: None, Basic Auth ou n8n User Auth. Evite None para dados internos [7].

4. CONCEITOS E GLOSSÁRIO
   - Agente de IA: sistema que interpreta um objetivo, decide passos e usa ferramentas. Analogia: um operador que escolhe qual utensílio usar [5].
   - Workflow: sequência visual de nós. Analogia: um fluxograma executável [1].
   - Trigger: nó que inicia a execução quando chega uma mensagem ou evento.
   - Chat Model/LLM: modelo que interpreta texto e decide a próxima resposta ou chamada de ferramenta.
   - System Message: instrução persistente que orienta decisões do agente; não é barreira de segurança [6][35].
   - Tool: capacidade externa disponibilizada ao agente, como consultar uma planilha ou chamar API [5][6].
   - Tool calling: o modelo escolhe uma ferramenta e preenche seus parâmetros com base no esquema publicado [6].
   - Memória: histórico associado a uma sessão para manter contexto entre mensagens [8].
   - Session Key: identificador usado para separar a conversa de cada usuário [8].
   - Context Window Length: quantidade de interações anteriores incluídas pela Simple Memory [8].
   - RAG: recuperação de trechos de fontes externas antes de gerar a resposta [9].
   - Embedding: representação numérica de um trecho, usada para comparar significado [9].
   - Vector Store: banco que guarda embeddings e encontra trechos semanticamente parecidos [9].
   - Chunk: trecho menor de um documento criado pelo data loader/text splitter [9].
   - Output Parser: componente que exige uma estrutura de saída, por exemplo JSON Schema [14].
   - Guardrail: validação externa ao modelo para entrada ou saída; pode bloquear jailbreak, PII, chaves, URLs ou assunto fora de escopo [15].
   - Human-in-the-loop: pausa para uma pessoa aprovar ou negar uma ferramenta antes da ação [16].
   - Evaluation: execução de casos de teste com resultados esperados e, opcionalmente, métricas [10][11].
   - MCP: protocolo para expor ou consumir ferramentas entre agentes e sistemas [12][13].
   - Execução: uma rodada completa do workflow; no Chat Trigger, cada mensagem é uma nova execução [7].

8. SEGURANÇA, PRIVACIDADE E DADOS
   - [CONFIRMADO] Credenciais self-hosted são criptografadas antes de ir ao banco; n8n gera uma chave no primeiro início ou aceita N8N_ENCRYPTION_KEY [19].
   - [CONFIRMADO] A telemetria não coleta o conteúdo que flui nos workflows nem o conteúdo das credenciais; em self-hosted, telemetria pode ser desativada, mas contagem de licença paga não [17].
   - [CONFIRMADO] No Cloud, n8n atua como controlador e processador sob GDPR; em self-hosted, o cliente responde pelos dados e pela exclusão [17]. Para LGPD, a equipe deve mapear base legal, minimização, finalidade, retenção, operador/controlador e direitos do titular. [SUGESTÃO] Validar com jurídico.
   - [CONFIRMADO] Use OAuth quando possível, TLS, criptografia em repouso, auditoria e bloqueio de nós arriscados [18][21].
   - [CONFIRMADO] Execution data redaction é Enterprise e oculta payloads no visualizador, mas não impede que nós seguintes ou webhooks recebam os dados [20].
   - [CONFIRMADO] Prompt injection pode vir diretamente da mensagem ou indiretamente de página/PDF/e-mail recuperado. O risco cresce quando o agente tem ferramentas amplas [35].
   Controles mínimos do exercício: documento não sigiloso; credencial de teste; operação limitada a uma planilha; confirmação do usuário; human review para gravar; Guardrails antes do modelo e na saída; não salvar segredos no prompt; separar sessão por usuário; revisar executions.

9. LIMITAÇÕES, ERROS COMUNS E SOLUÇÃO DE PROBLEMAS
   - “AI Agent exige ferramenta”: conecte ao menos uma Tool [5].
   - Agente não chama a ferramenta: dê nome e descrição inequívocos, informe quando chamar no System Message e verifique se o modelo suporta tool calling [6][40].
   - Loop ou custo alto: reduza “Max Iterations”, cujo padrão é 10, e crie condição clara de parada [6].
   - Memória misturada: Session Key não é exclusiva. Use identificador estável por usuário/conversa [8].
   - Simple Memory falha em produção com queue mode: use Postgres/Redis Chat Memory [8].
   - Chat “esquece”: em Chat Trigger, habilite “Load Previous Session” e conecte a mesma memória ao Chat Trigger e ao Agent [7].
   - Saída JSON inválida: habilite “Require Specific Output Format” e Structured/Auto-fixing Output Parser [6][14].
   - Ação duplicada após retry: retries podem reenviar o item ao nó que falhou; prefira operações idempotentes, como update/upsert, e confira o sistema de destino [38].
   - RAG responde sem fonte: force uso da ferramenta, inclua metadata e teste relevância dos chunks [9][11].
   - Erro de limite do provedor: reduzir concorrência, tamanho do contexto e frequência; avaliações paralelas aumentam risco de rate limit [11].
   - Fluxo conclui, mas resposta está errada: execução bem-sucedida não prova qualidade; crie dataset de avaliação e métricas [10][11].

10. COMPARAÇÃO COM ALTERNATIVAS
   [CONFIRMADO] O diferencial verificável do n8n é combinar workflows determinísticos, nós de IA/agentes, código, self-hosting e ferramentas de governança no mesmo canvas [1][3][39].
   [CONFIRMADO] Em n8n Cloud a cobrança baseia-se na execução completa, não em cada passo [3].
   [SUGESTÃO] Para automações previsíveis com etapas claras, um workflow determinístico tende a ser mais simples e barato que um agente. Use agente apenas onde houver decisão em linguagem natural [39].
   [SUGESTÃO] Zapier e Make reduzem responsabilidade de infraestrutura; n8n self-hosted oferece mais controle, mas exige atualização, backup e segurança. Comparar preço apenas com o mesmo volume e a mesma definição de execução/operação.
   [VERIFICAR] Uma comparação independente da TechRadar descreve n8n como forte em processos estruturados e repetíveis, mas ressalta maior esforço de configuração e manutenção que agentes mais autônomos [36]. É opinião editorial, não benchmark.
   Comparação quantitativa atual e independente entre n8n, Make e Zapier para AI Agent + RAG + ação: NÃO ENCONTRADO.

13. IDEIAS DE EXERCÍCIO
   Decomposição da tarefa observável:
   A. receber mensagens; B. consultar fontes; C. executar ações via workflow; D. manter contexto da sessão; E. comprovar e auditar resultado.
   [SUGESTÃO] Atividade 1 — Receber mensagens (A).
   Passos: Chat Trigger > Hosted Chat > AI Agent > Chat Model > ferramenta Calculator ou consulta simples. Teste público: página HTML do Chat Trigger; não exige arquivo externo. Resultado: mensagem aparece em Executions e recebe resposta. Fonte [7].
   [SUGESTÃO] Atividade 2 — Separar sessões (D).
   Passos: conectar Simple Memory, usar Session Key fornecida pelo Chat Trigger, enviar duas mensagens relacionadas e iniciar New Conversation. Resultado: follow-up usa contexto; nova sessão não reutiliza a anterior. Fonte [7][8].
   [SUGESTÃO] Atividade 3 — Consultar uma fonte (B).
   Passos: importar o RAG Starter Template público, carregar um PDF público curto, fazer pergunta cuja resposta esteja no documento. Link testado: https://n8n.io/workflows/5010-rag-starter-template-using-simple-vector-stores-form-trigger-and-openai — devolve página HTML pública; importar/copy pode exigir conta. Resultado: resposta corresponde ao PDF e a execução mostra chamada ao vector store. Fonte [9][29].
   [SUGESTÃO] Atividade 4 — Executar ação controlada (C).
   Passos: conectar Google Sheets Tool em uma planilha de teste; descrição limitada a append; pedir ao agente que prepare uma solicitação; human review antes de gravar. Link testado: https://n8n.io/workflows/15424-analyze-business-data-from-google-sheets-with-an-openai-chatbot/ — página HTML pública; workflow é comunitário. Resultado: uma linha criada após aprovação, nenhuma linha após negação. Fonte [16][41].
   [SUGESTÃO] Atividade 5 — Bloquear abuso e auditar (E).
   Passos: Guardrails antes do Agent; bloquear jailbreak/secret keys; enviar prompt adversarial; abrir Overview > Executions. Resultado: item segue para Fail e nenhuma Tool sensível é chamada. Fonte [15][38].
