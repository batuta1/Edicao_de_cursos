0. RESUMO EXECUTIVO
----------------------------------------------------------------
O Cursor é um editor de código (IDE) com IA embutida, derivado do VS Code, fabricado pela Anysphere. Hoje ele se apresenta como "a coding agent for building ambitious software" [11][72]: o centro do produto é o Agent, um assistente que lê o projeto, edita vários arquivos, roda comandos no terminal e testes. Serve a desenvolvedores e a quem já programa um pouco (inclusive quem vem de Lovable/Replit), porque o aluno descreve a tarefa em linguagem natural e revisa o resultado em "diffs".
O que mudou recentemente (abril a outubro de 2026): Cursor 3 com a Agents Window (abr/2026); compra da Anysphere pela SpaceX por US$ 60 bi (concluída em ago/2026); novo modelo comercial "The X Subscription" (Free, Plus US$ 8, Premium US$ 30, Super US$ 100, Ultra US$ 200), lançado em 12/10/2026, que junta Cursor, Grok e X [26][54]; modelos próprios Grok 4.x e Composer 2.5; Origin (hospedagem de código); app para iPhone.
TRÊS ALERTAS PARA QUEM VAI CRIAR O CURSO:
1) A "edição inline" (Cmd+K / Ctrl+K) FOI APOSENTADA em 26/10/2026. Hoje Cmd/Ctrl+K apenas abre o painel do Agent com o trecho selecionado [5][22][53]. A tarefa observável do curso ("usar chat, edição inline e agente") precisa ser reescrita pela equipe; ver seções 5, 11 e 13.
2) Planos e preços mudaram em 12/10/2026 e continuam instáveis: o plano gratuito (Free) e o Plus (US$ 8) NÃO dão acesso a modelos de terceiros (Claude, GPT, Gemini), a Cloud Agents nem ao Bugbot; isso só a partir do Premium (US$ 30) [30]. O desconto estudantil foi encerrado para novas adesões em 25/06/2026 [28]. Não há preço oficial em reais.
3) Dependência de fornecedores em movimento: a OpenAI anunciou em 28/08/2026 que vai encerrar o fornecimento de modelos ao Cursor (data proposta: 12/11/2026) [58][59]. Lista de modelos, nomes de planos e nomes de menus podem mudar antes de o curso ir ao ar. Além disso, a interface do Cursor não tem tradução oficial para o português (Agent/Chat em inglês) [66].

3. PRIMEIROS PASSOS (passo a passo oficial)
----------------------------------------------------------------
3.1 Instalar [CONFIRMADO] [2] (ajuda en)
 1. Ir a cursor.com/download.
 2. Clicar no botão de download do seu sistema.
 3. Abrir o arquivo baixado.
 4. Mac: arrastar o Cursor para a pasta Applications. Windows: rodar o instalador e seguir os passos. Linux: instalar via apt ou dnf, ou extrair o AppImage e executar.
 5. Abrir o Cursor pelo menu de aplicativos ou área de trabalho.
 6. Entrar (sign in) com a conta Cursor quando for pedido.
 "Get Cursor running on your machine in under five minutes." [2]

3.2 Importar configurações do VS Code [CONFIRMADO] [4] (ajuda en)
 1. Abrir Cursor Settings: Mac Cmd+Shift+J; Windows/Linux Ctrl+Shift+J.
 2. Ir a General > Account.
 3. Em "VS Code Import", clicar em "Import".
 Isso traz extensões, temas, configurações e atalhos. Alternativa: exportar um perfil no VS Code e importar manualmente [4].
 Atenção: o Cursor usa o registro Open VSX, não o Marketplace da Microsoft; nem toda extensão existe lá [4][45].

3.3 Abrir um projeto [CONFIRMADO] [3] (ajuda en)
 1. Abrir o Cursor.
 2. Clicar em File > Open Folder.
 3. Selecionar a pasta do projeto.

3.4 Primeiro uso do Agent [CONFIRMADO] [3][5] (ajuda en)
 1. Abrir o painel do Agent: Mac Cmd+I; Windows/Linux Ctrl+I.
 2. Digitar o pedido (exemplo oficial: "Add a dark mode toggle to the settings page.").
 3. Enviar (Return). O Agent explora o código, edita arquivos e mostra as mudanças.
 4. Acompanhar as edições na "diff view" e rejeitar o que não quiser.

3.5 Roteiro do Quickstart oficial [CONFIRMADO] [1]
 a) Instalar e entrar; escolher uma pasta e começar por uma tarefa pequena.
 b) Pedir ao Agent (Cmd I) que explique o projeto. Prompt oficial: "Explain this codebase. Point me to the main entry points, key modules, and anything I should read before making changes."
 c) Fazer uma mudança pequena. Prompt oficial: "Suggest three small, safe improvements in this codebase. Explain the tradeoffs and wait for me to choose one."
 d) Revisar o diff e pedir que o Cursor rode as verificações do projeto ("tests, the type checker, linting, or a local build").
 e) Para mudanças maiores, usar Plan Mode (Shift+Tab no campo do Agent).
 Observação: o Quickstart só mostra atalhos de Mac (Cmd). Equivalentes Windows/Linux usam Ctrl [3][22].

3.6 Duas "caras" do Cursor 3 [CONFIRMADO] [12]
- Editor clássico (IDE) e "Agents Window" (janela centrada em agentes). Para abrir a Agents Window no editor: Cmd+Shift+P > "Open Agents Window". Para voltar: Cmd+Shift+P > "Open IDE" (ajuda en). "You can switch back to the editor anytime, or have both open simultaneously."
- [SUGESTÃO] Para um curso Essentials, convém padronizar em UMA das duas interfaces (provavelmente o editor clássico, mais próximo do que o aluno de VS Code conhece) e citar a outra só como alternativa.

4. CONCEITOS E GLOSSÁRIO
----------------------------------------------------------------
(Definições simples em [SUGESTÃO] quando são redação nossa; analogias oficiais marcadas [CONFIRMADO] com fonte.)
- IDE (Integrated Development Environment / ambiente de desenvolvimento integrado): [SUGESTÃO] programa que junta num só lugar o editor de texto do código, o explorador de pastas, o terminal e ferramentas de teste e versão. Analogia: a "bancada de trabalho" do programador.
- Editor com "IA nativa": [SUGESTÃO] editor em que a IA não é um complemento instalado depois, mas faz parte do produto (autocompletar, chat e agente integrados ao editor, ao terminal e ao git).
- VS Code / fork: [SUGESTÃO] VS Code é o editor gratuito da Microsoft; "fork" é uma cópia do código-fonte que outra empresa passa a desenvolver por conta própria. Por isso o Cursor "parece" o VS Code e aceita boa parte de suas extensões [4][45].
- Agent (agente): [CONFIRMADO] "Agent is Cursor's AI assistant. It searches your codebase, edits multiple files, runs terminal commands, and fixes errors on its own." [5] Analogia oficial: "Think of agents like fast junior developers who need clear direction, who also can easily forget things, so they require oversight." [50 - capítulo Agents do Learn]
- Modelo (model / LLM): [CONFIRMADO] analogia oficial: "Think of these models like extremely powerful text autocomplete." [50 - How AI models work]
- Token: [CONFIRMADO] "You can think of tokens like the 'words' that AI models actually understand." [50 - Tokens & pricing]
- Contexto / janela de contexto (context window): [CONFIRMADO] "Every chat shares a fixed context window with the model." Quando enche, o Cursor resume partes antigas da conversa [15]. Analogia oficial: "Think of the context like a long list, where the AI model keeps a working memory for the conversation." [50 - Context]
- Anel de contexto (context ring): [CONFIRMADO] indicador ao lado do campo de prompt que mostra o quanto a janela está cheia; clicar abre o detalhamento (System prompt, Tools, Rules, Skills, MCP, Subagents, Summarized conversation, Conversation) [15].
- Tab: [CONFIRMADO] "Tab is Cursor's AI-powered autocomplete. It suggests code as you type" [6].
- Modos do Agent: Agent, Ask, Plan, Debug [CONFIRMADO] [5] (ver seção 5).
- Diff / diff view: [SUGESTÃO] tela que mostra lado a lado (ou em linhas verdes e vermelhas) o que foi acrescentado e o que foi removido no código. [CONFIRMADO] "The diff view shows changes made by the agent." [1]
- Checkpoint: [CONFIRMADO] "Checkpoints save snapshots of your codebase during an Agent session." São locais e separados do Git [11]. [SUGESTÃO] Analogia: "ponto de salvamento" de videogame.
- @ mention (menção com @): [CONFIRMADO] digitar @ no chat para anexar arquivos, pastas, terminais, chats anteriores, diffs do git ou o navegador ao pedido [19].
- Rules (regras): [CONFIRMADO] "Rules give Agent persistent instructions for your project." [24] Analogia oficial: "You can think of them as always-included instructions that shape how the agent works with your code." [50 - Customizing agents]
- AGENTS.md / CLAUDE.md: [CONFIRMADO] arquivos Markdown na raiz do projeto com instruções que o Cursor lê automaticamente [24].
- .cursorignore: [CONFIRMADO] arquivo que bloqueia o acesso do Agent/Tab/@ a arquivos e pastas [20][21].
- Privacy Mode: [CONFIRMADO] "Privacy Mode ensures your code is never used for training by Cursor or other AI model providers." [32]
- Run Mode / Auto-review / Allowlist / Sandbox: [CONFIRMADO] modos que decidem quando o Agent pode executar comandos sem pedir aprovação [18] (ver seção 8).
- Cloud Agents (antes "Background Agents"): [CONFIRMADO] agentes que rodam em máquinas virtuais na nuvem, "so you can close your laptop and check the result later" [40].
- Bugbot: [CONFIRMADO] "Bugbot reviews your pull requests and catches bugs, security issues, and code quality problems." [38]
- Pull request (PR): [SUGESTÃO] pedido para juntar ("mesclar") as alterações de um ramo ao código principal, com espaço para revisão e comentários.
- Commit / Git: [SUGESTÃO] Git é o sistema que guarda o histórico de versões do código; um commit é um "registro fotográfico" de um conjunto de mudanças com uma mensagem.
- MCP (Model Context Protocol): [CONFIRMADO] forma de conectar ferramentas externas; "All MCP connections need your approval." [17] (aprofundamento fica no curso MCP - Essentials).
- Subagente (subagent): [CONFIRMADO] agente especializado que o Agent cria para pesquisa, comandos ou navegador, "Each subagent runs in its own context window" [5].
- Skill: [CONFIRMADO] instruções reutilizáveis chamadas com "/" no chat; podem virar "Custom Mode" [15].
- Auto / Cursor Router: [CONFIRMADO] "Auto balances intelligence, cost, and reliability through Cursor Router." Nos planos individuais existe só o modo "Cost" (o antigo Auto) [26]. Observação: o plano Plus não inclui Auto [30].
- Pool semanal de uso: [CONFIRMADO] cota incluída no plano, renovada toda semana e compartilhada com o Grok [30].
- TDD (Test-Driven Development / desenvolvimento guiado por testes): [CONFIRMADO] o Learn oficial descreve o ciclo: escrever testes primeiro, confirmar que falham, fazer commit dos testes, pedir o código, fazer commit do código [48]. [SUGESTÃO] Analogia: escrever o gabarito da prova antes de resolver a prova.
- Teste unitário: [SUGESTÃO] pequeno programa que verifica automaticamente se uma função devolve o resultado esperado; "passou" (verde) ou "falhou" (vermelho).
- Linter / type checker: [CONFIRMADO] no Learn: "Linting catches style and pattern violations"; "Type checking catches structural errors" [49].
- Prompt injection / alucinação: [CONFIRMADO] "AI can behave unexpectedly due to prompt injection, hallucinations, and other issues." [17]
- Worktree: [CONFIRMADO] cópia isolada do repositório Git para cada agente trabalhar sem misturar mudanças [12].
- Origin: [CONFIRMADO] hospedagem de código/git do próprio Cursor (planos Premium e acima) [30]. Fora do escopo do Essentials.

----------------------------------------------------------------
(Para cada uma: o que faz / onde fica / plano / limitações. Nomes (ajuda en).)

5.1 Tab (autocompletar)
- [CONFIRMADO] Sugere código enquanto se digita, com base em edições recentes, código ao redor e erros do linter. Aceitar tudo: Tab. Rejeitar: Esc ou continuar digitando. Aceitar palavra a palavra: Mac Cmd+Seta direita; Win/Linux Ctrl+Seta direita. Sugestões aparecem em cinza [6].
- [CONFIRMADO] Edita várias linhas, adiciona imports e sugere edições coordenadas; após aceitar, apertar Tab de novo leva ao próximo ponto de edição ("jump-in-file"); pode sugerir edições em outro arquivo ("portal window" no rodapé) [6].
- [CONFIRMADO] Ligar/desligar: clicar no indicador "Tab" no canto inferior direito (Snooze, Disable globally, Disable for specific extensions) ou Cursor Settings > Tab [6].
- Plano: [CONFIRMADO] Free inclui "Tab completions" [26]. NÃO ENCONTRADO: limite numérico de sugestões no Free.
- [CONFIRMADO] Regras (Rules) não se aplicam ao Tab [24].

5.2 Edição inline (Cmd+K / Ctrl+K) — APOSENTADA
- [CONFIRMADO] "Select the code, then press Cmd + L or Cmd + K on Mac (Ctrl + L or Ctrl + K on Windows/Linux). Agent opens with those lines referenced in the input, ready for your instructions. Cmd + K used to open inline edit, which has been replaced by this workflow." [5]
- [CONFIRMADO] (fórum oficial, resposta de funcionário da Cursor) Data: 26/10/2026. A mensagem exibida é "Cmd+K Has Been Retired. Select code and press Cmd+L to add it to Agent." Motivo dado: "Use of Cmd+K had dropped a long way from its peak as more of this kind of work moved into Agent, and keeping a second inline system maintained alongside Agent was no longer something we could justify, so it was folded into Agent." - [CONFIRMADO] Dica do mesmo funcionário para pedidos rápidos: escolher modelo mais leve, "Composer 2.5 with Fast on, Grok 4.7 with effort on Low and Fast on" [53]. Observação: no plano Plus o Fast fica desligado [30].
- [VERIFICAR] Reação da comunidade: muitos usuários pedem a volta do recurso [53]; a decisão pode ser revista. Monitorar antes de gravar o curso.
- Tabela de atalhos oficial atual: "Cmd L or Cmd K: Add selection to new chat"; "Cmd Shift L: Add selection to Chat" [23].

5.3 Agent (chat/agente) e seus modos
- [CONFIRMADO] Abrir: Cmd+I (Mac) / Ctrl+I (Win/Linux). Também Cmd/Ctrl+L ou K com código selecionado [5][22].
- [CONFIRMADO] Modos atuais e para que servem [5]:
  Agent: construir funcionalidades, refatorar, corrigir bugs — edita arquivos: sim.
  Ask: entender código, explorar arquitetura — edita: não (somente leitura).
  Plan: funcionalidades complexas em que se quer revisar a abordagem antes — edita: sim, após aprovar o plano.
  Debug: bugs difíceis que precisam de evidência em tempo de execução — edita: sim.
- [CONFIRMADO] Trocar de modo: Shift+Tab (alterna) ou menu suspenso de modos no painel; menu de modos: Cmd+. / Ctrl+. [5][22]. "Each mode uses its own context, so switching modes starts a fresh context window." [5]
- [CONFIRMADO] No editor e na CLI também funcionam comandos "/ask ..." e "/plan ..." (correção registrada nas notas de versão) [47].
- [CONFIRMADO] Ferramentas do Agent: buscar arquivos e pastas, Web (pesquisa na web), Fetch Rules, ler arquivos (inclusive imagens), editar arquivos, rodar comandos de terminal, Browser (controlar navegador), gerar imagens, fazer perguntas de esclarecimento. "There is no limit on the number of tool calls Agent can make during a task." [11]
- [CONFIRMADO] Interromper: botão "Stop" [5]; atalho "Cmd Shift Backspace: Cancel generation" [23].
- [CONFIRMADO] Fila de mensagens: Enter enfileira; Cmd+Enter envia na hora [11]. "Steer" (corrigir o rumo sem interromper): "Send now" ou Enter duas vezes, em implantação [11].
- [CONFIRMADO] Side chats: "/side" ou "/btw" para tirar uma dúvida paralela sem atrapalhar a conversa principal [11].
- [CONFIRMADO] "/goal" para um objetivo de longa duração — "rolling out" (instável) [11].
- [CONFIRMADO] Entrada por imagem (arrastar ou colar com Cmd+V) e por voz (ícone de microfone) [15].
- Plano: [CONFIRMADO] Agent e Chat existem no Free "with limited usage" [30].

5.4 Plan Mode
- [CONFIRMADO] Passo a passo [8]: abrir o Agent (Cmd/Ctrl+I) > Shift+Tab até "Plan" > digitar o pedido > Return > o Agent pesquisa e pode fazer perguntas > revisar o plano (abre como arquivo virtual editável) > clicar "Build" para começar a codar.
- [CONFIRMADO] Planos ficam na pasta pessoal; "Save to workspace" move para o projeto [8].
- [CONFIRMADO] Recomeçar: botão "Revert" no canto inferior direito de uma mensagem anterior > "Confirm"; refinar o plano e rodar de novo [8].

5.5 Ask Mode
- [CONFIRMADO] Modo somente leitura; exemplos oficiais de perguntas: "How does the authentication flow work?", "What does this function do?", "Where is the database connection configured?" [7].

5.6 Debug Mode
- [CONFIRMADO] O agente levanta hipóteses, adiciona logs, pede que você reproduza o bug, analisa os logs, faz uma correção pequena e remove a instrumentação [16].

5.7 Escolha de modelo

7. BOAS PRÁTICAS E EXEMPLOS DE PROMPTS
----------------------------------------------------------------
7.1 Publicados pela fabricante (texto original em inglês) [CONFIRMADO]
- Entender o projeto: "Explain this codebase. Point me to the main entry points, key modules, and anything I should read before making changes." [1]
- Mudança segura: "Suggest three small, safe improvements in this codebase. Explain the tradeoffs and wait for me to choose one." [1]
- Exemplo de pedido ao Agent: "Add a login form to the homepage with email and password fields." [5]
- Ask: "How does the authentication flow work?" / "What does this function do?" [7]
- Revisão: "Review the changes I've made to the discount code feature. Look for bugs, missing error handling, and anything that doesn't match our patterns in [arquivo]" [49]
- Testes: "Write integration tests for the discount code API endpoint and e2e tests for the checkout discount flow. Look at our existing test patterns and match them." [49]
- Outros prompts de teste do Learn: "What edge cases aren't covered by our current tests for the discount feature?"; "Write regression tests for the bug we fixed in PaymentService.ts." [49]
- TDD, passo 1: "Write tests for a discountCode() function that: - Returns the discounted price when given a valid code - Throws InvalidCodeError for expired codes - Applies fixed-amount discounts correctly (e.g., "10OFF" = $10 off) - Never returns a negative price (floor at $0) Follow the test patterns in [arquivo]. Do NOT write the function yet." [48]
- TDD, passo 2: "Make all tests in [arquivo de teste] pass. Follow the service patterns in [arquivo]. Do NOT modify the tests." [48]
- Exploração com subagente: "use a subagent to find all the places we validate user input." [51]
7.2 Boas práticas oficiais [CONFIRMADO]
- "Be specific in your prompts: include expected behavior and constraints"; usar Plan mode antes em tarefas que tocam muitos arquivos; "Start a new chat when you finish a feature or switch tasks"; criar regras para padrões repetidos; usar @ para contexto dirigido [46].
- "Good first tasks are low risk, like improving some copywriting or fixing small UI issues." [1]
- Quando o agente erra o rumo, voltar ao plano: "Revert the changes, refine the plan to be more specific about what you need, and run it again." [14]
- Dar ao agente formas de se verificar: testes, checagem de tipos, linters, navegador/MCP [48][49].
- "Passing tests don't guarantee the code works correctly. It's possible the tests are checking the wrong behavior." [49]
- Commits pequenos e semânticos, para facilitar revisão [49].
- Regras: manter abaixo de 500 linhas, começar pequeno, versionar no git [24].
- Modelo: "Faster models work well for quick edits and routine tasks"; "More capable models are better for complex reasoning and multi-file refactoring" [15].
7.3 Prompts em português escritos por nós
- [SUGESTÃO] Ask: "Explique, em português e para alguém iniciante, o que faz o arquivo @gilded_rose.py. Liste as regras de negócio que você encontrou."

- [SUGESTÃO] Revisão: "Revise as mudanças deste chat. Há casos de borda sem teste?"

8. SEGURANÇA, PRIVACIDADE E DADOS
----------------------------------------------------------------
8.1 Privacy Mode
- [CONFIRMADO] Ativar: Cursor Settings (Cmd/Ctrl+Shift+J) > General > Privacy Mode (ajuda en) [32].
- [CONFIRMADO] "Privacy Mode ensures your code is never used for training by Cursor or other AI model providers." [32]
- [CONFIRMADO] Em times, Privacy Mode vem ligado por padrão e pode ser imposto pelo administrador [32]; "Privacy Mode is on by default for Enterprise teams." [35]
- NÃO ENCONTRADO: se Privacy Mode vem ligado ou desligado por padrão em contas individuais/gratuitas. Procurado em [32][35][36][37]. A página de segurança diz que o modo está disponível "on both free and Pro plans" [37].
- [CONFIRMADO] Com Privacy Mode desligado, o Cursor pode usar e armazenar dados do código, prompts e ações para melhorar a IA e treinar modelos (página Data Use, atualizada em 03/09/2026) [36].
8.2 Para onde vai o código / retenção
- [CONFIRMADO] "When you use AI features, Cursor sends prompts and code context to model providers like OpenAI, Anthropic, and Google." [32]
- [CONFIRMADO] Acordos de "zero data retention" (ZDR) com provedores; exceções: uso de chave de API própria e modelos que exigem retenção (ex.: Claude Fable 5 e 5.1), que pedem aprovação [32][35].
- [CONFIRMADO] "Cloud Agents are the only feature that requires Cursor to store code." Cópias criptografadas, temporárias, apagadas ao fim [35].
- [CONFIRMADO] Busca local: Instant Grep "builds and queries its index on your machine" [51].
- [VERIFICAR] Governança do código hospedado no Origin ainda não está clara (críticas na imprensa) [62].
- [CONFIRMADO] Privacy Mode do editor não cobre o Grok Bot, que "runs on a separate product surface with its own data flows" [32].
8.3 Certificações
- [CONFIRMADO] "AIUC-1, ISO/IEC 27001:2022, and ISO/IEC 42001:2023 certifications, along with a SOC 2 Type II attestation" (página Security, atualizada em 25/08/2026) [37]. Relatórios sob pedido em trust.cursor.com [33].
- [CONFIRMADO] "Cursor does not use or maintain any infrastructure in China." [37]
8.4 Execução de comandos no terminal (riscos e lista de permissões)
- [CONFIRMADO] Onde: Cursor Settings > Agents > Approvals & Execution (ajuda en) [10][18]. Modos (Cursor 3.6+): "Auto-review" (padrão), "Allowlist", "Run Everything" [10].
  Auto-review: comandos da lista rodam; o resto roda no sandbox quando possível; o que sobrar passa por um classificador de IA [10][18].
  Allowlist: só comandos da lista rodam sem aprovação [10].
  Run Everything: tudo roda sem aprovação; "Use Auto-review instead if you want most calls to run without prompting." [10]
- [CONFIRMADO] "Auto-review is not a security boundary" — o classificador pode errar [18].
- [CONFIRMADO] Antes da 3.5 os modos eram "Run in Sandbox", "Ask Every Time" e "Run Everything"; "Ask Every Time" foi descontinuado [10].
- [CONFIRMADO] Para ver cada comando antes de rodar: Allowlist com a lista vazia (dica de funcionário no fórum) [53].
- CONTRADIÇÃO [VERIFICAR]: a página Agent Security diz "By default, terminal commands need your approval" [17], enquanto a ajuda do terminal diz que o padrão é Auto-review, em que parte dos comandos roda sem perguntar [10].
- [CONFIRMADO] "Agents can modify workspace files without approval, except for configuration files. Changes save immediately to disk. Always use version control so you can revert changes." [17]
- [CONFIRMADO] MCP: cada conexão e cada chamada de ferramenta exigem aprovação, salvo lista de pré-aprovação [17].
- [CONFIRMADO] Workspace trust vem desligado por padrão; "For untrusted repos, use a basic text editor instead." [17]
8.5 Arquivos de exclusão (.cursorignore)
- [CONFIRMADO] Criar .cursorignore na raiz, com sintaxe de .gitignore [20][21]. O Cursor já ignora por padrão arquivos .env, .git/ e lock files, além do que estiver no .gitignore [20].
- [CONFIRMADO] Limitação: "Terminal commands and MCP tools run outside of Cursor's file access controls, so they may still be able to read ignored files." [20] E: "complete protection isn't guaranteed due to LLM unpredictability." [21]
8.6 Extensões
- [CONFIRMADO] Extensões vêm do Open VSX via proxy do Cursor com análise automática de malware; "Treat extension IDs like dependencies: install from publishers you trust." [45]
8.7 LGPD e dados sigilosos
- [CONFIRMADO] Para planos individuais o DPA (acordo de processamento de dados) não se aplica; vale a Política de Privacidade [32]. Residência de dados só nos EUA (opção Enterprise) [34].
- NÃO ENCONTRADO: menção à LGPD na documentação do Cursor. Procurado em [32][35][36][37].
- [SUGESTÃO] Orientar o aluno a não abrir no Cursor projetos com dados pessoais reais, a manter .env fora do contexto, a ligar o Privacy Mode e a usar o git antes de pedir mudanças.

9. LIMITAÇÕES, ERROS COMUNS E SOLUÇÃO DE PROBLEMAS
----------------------------------------------------------------
- [CONFIRMADO] Agent não "vê" arquivos: conferir .cursorignore e .gitignore; reindexar ("Reindex" na paleta de comandos); anexar com @ [46].
- [CONFIRMADO] Desfazer: "Restore Checkpoint" [46].
- [CONFIRMADO] Erro "Agent Execution Timed Out": o extension host não iniciou em 60 s; exportar logs em Cmd/Ctrl+Shift+P > "Developer: Export Logs..." [46].
- [CONFIRMADO] CI=1 nos comandos do Agent pode alterar o comportamento de projetos [46].
- [CONFIRMADO] Temas de shell pesados (Powerlevel10k) podem truncar a saída do terminal [74].
- [CONFIRMADO] Fim do pool semanal: notificação no editor; aguardar, pagar créditos ou subir de plano [29].
- [CONFIRMADO] "Model not available": restrição regional do provedor; usar Auto ou outro modelo [31]. Observação: Auto não existe no Plus [30].
- [CONFIRMADO] "Move to Cloud" não leva alterações não commitadas [41].
- [CONFIRMADO] Regras não aplicam: conferir tipo da regra e descrição; regras não valem para Tab nem para Bugbot [24].
- [CONFIRMADO] Arquivos .md dentro de .cursor/rules são ignorados; regras de projeto precisam de extensão .mdc [25].
- [CONFIRMADO] Atrás de VPN/firewall a CLI precisa liberar *.cursor.sh e *.cursorapi.com [43].
- [VERIFICAR] Fórum (comunidade): após o fim do Cmd+K, usuários relatam que o Agent é mais lento para edições pequenas [53].
- [VERIFICAR] Built In: em teste de seis meses, interface com "UI clutter" que atrapalha o ciclo de TDD [56].
- [CONFIRMADO] Limitação de segurança importante: "Restricted mode breaks AI features." (workspace trust) [17].

10. COMPARAÇÃO COM ALTERNATIVAS
----------------------------------------------------------------
Fatos com fonte:
- [VERIFICAR] Built In, 13/05/2026, teste de seis meses (fonte independente, única): Cursor é o único dos quatro que é uma IDE completa (fork do VS Code) com troca de modelos; Claude Code mais forte em planejamento e contexto do projeto; Codex melhor em refatorações autônomas em nuvem; GitHub Copilot melhor para empresas já no GitHub Enterprise [56].
- [VERIFICAR] Stack Overflow Developer Survey 2026 (via Visual Studio Magazine): uso entre quem usa agentes — Claude Code 65,5%, Codex 29,5%, Cursor 25,5% [57].
- [CONFIRMADO] O próprio Cursor lê CLAUDE.md "the same way it reads AGENTS.md", para compatibilidade com projetos que usam Claude Code [24].
- [CONFIRMADO] Planos gratuito e Plus do Cursor não incluem modelos de terceiros (Claude, GPT, Gemini) [30]; isso o diferencia de ferramentas presas a um só fornecedor e, ao mesmo tempo, encarece o acesso a esses modelos.
- [VERIFICAR] Mudança de cenário: após a compra pela SpaceX, a OpenAI anunciou o fim do fornecimento de modelos ao Cursor [58][59].
Conclusões nossas:
- [SUGESTÃO] Fronteira com os outros cursos da trilha: o Cursor é um editor completo (IDE própria); Claude Code e Codex são agentes que rodam em terminal/extensão/nuvem; GitHub Copilot é extensão dentro do VS Code e de outras IDEs. Basta um quadro comparativo simples, sem aprofundar os concorrentes.
- [SUGESTÃO] Não usar comparações de sites com conflito de interesse (ex.: nxcode.io, que declara publicar o próprio produto) como base.

13. IDEIAS DE EXERCÍCIO
----------------------------------------------------------------
13.1 Decomposição da tarefa observável
Tarefa: "Usar chat, edição inline e agente para implementar uma funcionalidade com testes."
Ações (verbos):
 A1. Usar o chat para entender o código (hoje: Agent em modo Ask) — passo a passo oficial: [7] (seção 3.4/5.5).
 A2. Fazer edição inline — ATENÇÃO: recurso aposentado em 26/10/2026 [5][53]. Equivalentes atuais: (a) Tab, para edições no próprio arquivo [6]; (b) selecionar código + Cmd/Ctrl+L (ou K) para enviar o trecho ao Agent e pedir uma edição localizada [5]. [SUGESTÃO] A equipe deve decidir como reescrever esta parte da tarefa (ex.: "editar um trecho selecionado com o Agent").
 A3. Usar o agente para implementar (Agent e, de preferência, Plan) — passo a passo oficial: [8][5].
 A4. Escrever testes (pedir ao agente) — fonte oficial: [48][49].
 A5. Rodar testes e confirmar o resultado — o Agent roda comandos no terminal conforme o Run Mode [10]; o Quickstart orienta pedir "the checks your project already uses" [1].
 A6. Revisar e desfazer (diff, Restore Checkpoint) — [5][11].

13.2 Projetos públicos testados para os exercícios (todos responderam HTTP 200 em 03/11/2026, licença MIT, sem login)
 P1. Gilded Rose Refactoring Kata (Emily Bache) — https://github.com/emilybache/GildedRose-Refactoring-Kata (página HTML do GitHub). Versões Python (pasta python/, testes com "python -m unittest") e JavaScript com Jest (pasta js-jest/, "npm test"). Download direto do projeto inteiro: https://github.com/emilybache/GildedRose-Refactoring-Kata/archive/refs/heads/main.zip (devolve arquivo ZIP, 872 arquivos). Requisitos OFICIAIS EM PT-BR: https://github.com/emilybache/GildedRose-Refactoring-Kata/blob/main/GildedRoseRequirements_pt-BR.md (página HTML). A funcionalidade a implementar é o item "Conjurado" (Conjured), que perde qualidade duas vezes mais rápido. Atenção: o teste inicial vem propositalmente falhando (espera o nome "fixme").
 P2. Theatrical Players Refactoring Kata (Emily Bache, a partir do livro Refactoring de Martin Fowler) — https://github.com/emilybache/Theatrical-Players-Refactoring-Kata (HTML). Pastas python/ (pytest, approval tests) e javascript/. Funcionalidades sugeridas pelo próprio README: imprimir o extrato em HTML ou acrescentar novos tipos de peça ("history", "pastoral"). ZIP: https://github.com/emilybache/Theatrical-Players-Refactoring-Kata/archive/refs/heads/main.zip (devolve ZIP, 308 arquivos). Requisitos só em inglês.
 P3. NÃO ENCONTRADO um terceiro projeto em pt-BR com testes já configurados. [SUGESTÃO] Alternativa: o próprio Gilded Rose em JavaScript conta como segunda linguagem.
 Observação: os exercícios exigem Python 3 ou Node.js instalados; o curso não ensina a instalá-los (pré-requisito "noções de programação"). [SUGESTÃO] a equipe pode indicar que o aluno peça ao Agent para verificar/instalar dependências.

13.3 Atividades [todas SUGESTÃO]
 E1 (A1 – chat/Ask). Abrir a pasta python/ do Gilded Rose (File > Open Folder), abrir o Agent (Ctrl/Cmd+I), mudar para Ask (Shift+Tab) e pedir: "Explique em português as regras do método update_quality." Prova de que deu certo: a resposta cita Aged Brie, Sulfuras, Backstage passes e o limite de qualidade 50, e nenhum arquivo aparece como alterado.
 E2 (A2 – edição localizada, substituto da edição inline). Selecionar o teste test_foo, apertar Ctrl/Cmd+L e pedir "Corrija este teste para esperar o nome 'foo'". Rodar "python -m unittest". Prova: 1 teste, OK. Variante com Tab: começar a digitar um novo teste e aceitar a sugestão com Tab.
 E3 (A3 – Plan). Em Plan, pedir o plano para itens Conjured com base em @GildedRoseRequirements_pt-BR.md; ler o plano e clicar "Build" só depois de revisar. Prova: um plano com arquivos e testes listados, editável antes da construção.
 E4 (A4/A5 – TDD). Pedir: testes para Conjured, sem implementar; rodar e ver falhar (vermelho). Depois: "faça os testes passarem sem alterar os testes". Prova: saída do terminal com todos os testes OK; diff mostrando mudança em gilded_rose.py e não nos testes.
 E5 (A6 – revisar e desfazer). Pedir uma mudança qualquer, olhar o diff, usar Restore Checkpoint numa mensagem anterior e conferir que o arquivo voltou. Prova: o arquivo volta ao estado anterior; a conversa continua visível.
 E6 (segurança). Conferir Cursor Settings > Agents > Approvals & Execution e Privacy Mode; criar .cursorignore com ".env". Prova: o Agent informa que não consegue ler o arquivo ignorado via @.
 E7 (variação JS). Repetir E4 em js-jest/ com "npm install" e "npm test".
 Plano: as atividades usam Agent/Chat/Tab, disponíveis no Free com uso limitado [26][30]; volume de uso do Free NÃO ENCONTRADO — [VERIFICAR] se cabe uma sequência de exercícios dentro do limite semanal gratuito.

1. O que é o Cursor, Anysphere, relação com o VS Code, IDE e "IA nativa"
 - [CONFIRMADO] "Cursor is a coding agent for building ambitious software." [72]. Fabricante: Anysphere (fundada em 2022) [55], desde ago/2026 parte da SpaceX/SpaceXAI [55] [VERIFICAR datas].
 - [CONFIRMADO] Compatível com VS Code: importa extensões, temas, configurações e atalhos; mesmos atalhos padrão; pode rodar ao lado do VS Code [4]. Usa Open VSX em vez do Marketplace da Microsoft [45].
 - [VERIFICAR] É um fork do VS Code (imprensa independente [56][65]; a ajuda oficial lida não usa o termo).
 - IDE e "IA nativa": definições na seção 4 [SUGESTÃO].
2. Instalação por sistema, requisitos, importação do VS Code, login, primeiro projeto
 - [CONFIRMADO] Seções 2.6, 3.1 a 3.4 [1][2][3][4].
3. Recursos centrais com nomes e atalhos atuais
 - Tab: Tab aceita; Esc rejeita; Ctrl/Cmd+Seta direita aceita palavra [6].
 - Edição inline: aposentada em 26/10/2026; Ctrl/Cmd+K ou L com seleção abre o Agent com o trecho [5][53].
 - Chat/agente: Ctrl/Cmd+I; modos Agent, Ask, Plan, Debug; Shift+Tab alterna; Ctrl/Cmd+. abre menu de modos [5][22].
 - Modelo: seletor no topo do campo; Ctrl/Cmd+/ alterna [15].
 - Contexto @: arquivos, pastas, @Terminals, @Chats, @Commit, @Branch, @Browser [19]. Web: ferramenta de busca do Agent [11]. Documentação (@Docs): NÃO ENCONTRADO na documentação atual.
 - Checkpoints: "Restore Checkpoint" [5][11].
 - Diffs: diff view; Ctrl/Cmd+Enter aceita tudo; Ctrl/Cmd+Shift+Backspace rejeita tudo [23]; aba Changes; Agent Review [13].
 - Terminal: Agent roda comandos conforme Approvals & Execution [10].
 - Observação: a tabela de atalhos da documentação de referência só mostra teclas de Mac [23]; a ajuda dá Mac e Windows/Linux [22].
4. Regras, AGENTS.md, memórias e documentação indexada
 - [CONFIRMADO] Regras de projeto: Ctrl/Cmd+Shift+P > "New Cursor Rule" > nome > instruções em Markdown > tipo (Always Apply, Apply Intelligently, Apply to Specific Files, Apply Manually) > salvar em .cursor/rules/ (arquivos .mdc) [24][25].
 - [CONFIRMADO] Regras de usuário: "Customize" na barra lateral > "Rules" [24].
 - [CONFIRMADO] AGENTS.md na raiz é lido automaticamente; CLAUDE.md também, sempre aplicado [24].
 - [CONFIRMADO] Regras de time (Teams/Enterprise) com precedência Team > Project > User [24].
 - [CONFIRMADO] .cursorrules é legado e será descontinuado [24].
 - Memórias (Memories): NÃO ENCONTRADO como recurso na documentação atual (procurado em [24][25][11][72]; a doc só diz que "Large language models don't retain memory between completions. Rules provide persistent, reusable context" [25]). O Agent pode buscar em conversas passadas ("Conversation search") [5].
 - Documentação indexada: NÃO ENCONTRADO na documentação atual; existe indexação do próprio código do projeto ("Codebase indexing", busca semântica, comando "Reindex") [46][47].
5. Agentes na nuvem, Bugbot, CLI — o que existe e em qual plano
 - [CONFIRMADO] Cloud Agents (antigos Background Agents): rodam em VM na nuvem, abrem PR, anexam vídeo/screenshots; iniciar pelo botão "Cloud" ao lado do campo do agente, em cursor.com/agents, ou mencionando @Cursor no Slack/GitHub/Linear [40][41]. Plano: Premium ou superior (não no Free nem no Plus) [30]. Correção automática de CI: Teams e Enterprise [41].
 - [CONFIRMADO] Bugbot: revisão automática de pull requests; configurar em cursor.com/dashboard > Integrations; acionar manualmente comentando "cursor review" ou "bugbot run"; regras em .cursor/BUGBOT.md [38]. Cobrança por uso desde a mudança de maio/2026 [39]. Plano: Premium ou superior [30].
 - [CONFIRMADO] CLI: instalar com "curl https://cursor.com/install -fsS | bash" (macOS/Linux/WSL) ou "irm 'https://cursor.com/install?win32=true' | iex" (PowerShell); comando "agent"; modos Agent, Plan, Ask; modo não interativo "-p" [42][43]. Plano: NÃO ENCONTRADO restrição explícita de plano para a CLI; o pool de uso é compartilhado com a CLI [30].
 - [CONFIRMADO] Agent Review (revisão local, dentro do editor) [13]. Plano: NÃO ENCONTRADO.

 - [CONFIRMADO] O Agent pode "write tests" e rodar comandos de terminal [5][10]; pedir ao fim "tests, the type checker, linting, or a local build" [1].
 - [CONFIRMADO] Alerta oficial: testes que passam não garantem código correto [49].

19. APÊNDICE TÉCNICO
----------------------------------------------------------------
- Instalação Linux (Debian/Ubuntu), comandos oficiais [1]: adicionar a chave GPG (curl -fsSL https://downloads.cursor.com/keys/anysphere.asc | gpg --dearmor | sudo tee /etc/apt/keyrings/cursor.gpg), adicionar o repositório https://downloads.cursor.com/aptrepo stable main, depois "sudo apt update" e "sudo apt install cursor". RHEL/Fedora: repositório https://downloads.cursor.com/yumrepo e "sudo dnf install cursor". AppImage: "chmod +x Cursor-*.AppImage" e executar.
- Regras de projeto: arquivos .mdc com frontmatter (description, globs, alwaysApply) em .cursor/rules/ [25].
- Auto-review: lê ~/.cursor/permissions.json e <projeto>/.cursor/permissions.json com "allow_instructions" e "block_instructions" em linguagem natural; o classificador usa "Gemini 3.5 Flash Lite" com Haiku de reserva [18].
- Sandbox: comandos rodam com limites de arquivo e rede; configuração via sandbox.json [18][74].
- Variável CURSOR_AGENT para detectar quando o shell é aberto pelo Agent [74].
- Workspace trust: "security.workspace.trust.enabled": true no settings.json do usuário [17].
- .cursorignore: sintaxe .gitignore; opção Cursor Settings > Indexing > Ignore Files > Hierarchical Cursor Ignore; lista global vazia por padrão [21].
- CLI: autenticação com "agent login" ou variável CURSOR_API_KEY; "agent update"; modo não interativo "agent -p"; "&" envia tarefa a um Cloud Agent [42][43].
- Subagentes personalizados: arquivos Markdown em .cursor/agents/ [5]. Hooks em .cursor/hooks.json [41].
- Bugbot: limites de regra de 30.000 caracteres por regra e 100.000 por revisão; "bugbot run verbose=true" para diagnóstico [38].
- Cursor Router (Teams/Enterprise): modos Cost, Balance, Intelligence; Cursor Token Rate de US$ 0,25 por milhão de tokens em certos casos [26][29].
- Agent SDK, Origin, Grok Bot, Self-Hosted Machines, APIs administrativas: existem (ver sitemap [72]), fora do escopo.
