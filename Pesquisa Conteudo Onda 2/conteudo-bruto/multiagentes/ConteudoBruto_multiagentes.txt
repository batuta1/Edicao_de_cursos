0. RESUMO EXECUTIVO
================================================================

[CONFIRMADO] A Anthropic distingue dois tipos de sistema: workflows, em que LLMs
e ferramentas seguem caminhos definidos em código, e agentes, em que o LLM dirige
dinamicamente o próprio processo e o uso de ferramentas. A recomendação central é
"encontrar a solução mais simples possível e só aumentar a complexidade quando
necessário". [10]

[CONFIRMADO] Um sistema multiagente reúne vários agentes autônomos que interagem
num ambiente compartilhado; cada um se especializa num domínio e eles se
coordenam por comunicação, memória compartilhada e lógica de orquestração. [19]

[CONFIRMADO] Vários agentes ajudam quando o trabalho pode ser dividido em partes
independentes. No sistema de pesquisa da Anthropic, um agente líder (Opus 4) com
subagentes paralelos (Sonnet 4) superou um único agente Opus 4 em 90,2% na
avaliação interna, mas consumiu cerca de 15 vezes mais tokens que um chat
(agentes isolados: cerca de 4 vezes). A própria Anthropic diz que tarefas de
programação e tarefas que exigem contexto compartilhado ou muitas dependências
entre agentes são encaixes ruins. [9]

[CONFIRMADO] Estudo controlado do Google Research (180 configurações, 3 famílias
de modelos, 4 benchmarks) mostrou que coordenação centralizada melhorou 80,9% uma
tarefa financeira paralelizável, mas todas as variantes multiagente pioraram de
39% a 70% numa tarefa de planejamento sequencial (PlanCraft). Agentes
independentes, sem comunicação, amplificaram erros 17,2 vezes; o modelo
centralizado conteve a amplificação em 4,4 vezes. [25][39]

[CONFIRMADO] Uma taxonomia acadêmica de falhas (MAST, NeurIPS 2025) identificou 14
modos de falha em 3 categorias: problemas de especificação, desalinhamento entre
agentes e verificação/término da tarefa. Os autores observam que os ganhos dos
sistemas multiagente sobre agentes únicos em benchmarks populares muitas vezes
são mínimos. [26]

[CONFIRMADO] No Claude Code, em 18/11/2026, há cinco formas de trabalho paralelo:
subagentes (dentro de uma sessão, devolvem um resumo), agent view (sessões em
segundo plano, research preview), agent teams (líder + colegas com lista de
tarefas e mensagens; experimental e desligado por padrão), projects (beta
público) e dynamic workflows (script que orquestra dezenas a centenas de
subagentes). [4]

[CONFIRMADO] O Claude Code exige plano Pro, Max, Ultra, Team, Enterprise ou conta
Console; o plano gratuito do claude.ai não inclui Claude Code. Pro custa US$ 20/mês
(US$ 17/mês no anual). [7][8]

[CONFIRMADO] No n8n, o padrão multiagente principal é o nó AI Agent Tool: um AI
Agent "raiz" chama outros agentes como ferramentas, e esses nós podem ser
aninhados em várias camadas. Sub-workflows entram como ferramentas pelo nó Call
n8n Workflow Tool. Desde a versão 2.6 (26/01/2026) existe revisão humana por
ferramenta; na 2.40 (21/09/2026) surgiu o recurso Agents (Preview), com
subagentes, canais e agendamentos. [12][13][14][16][17]

[CONFIRMADO] O n8n afirma que sistemas multiagente "podem facilmente consumir
10–20x os tokens de um workflow de agente único" e recomenda roteamento
determinístico (Switch) quando a categoria é conhecida: "use roteamento
determinístico quando puder, roteamento por agente quando precisar". [20]

[CONFIRMADO] Riscos específicos de multiagentes estão no OWASP Top 10 for Agentic
Applications 2026 (publicado em 09/12/2025): ASI07 comunicação insegura entre
agentes, ASI08 falhas em cascata e ASI10 agentes desonestos/comprometidos, além
de sequestro de objetivo (ASI01) e abuso de identidade e privilégio. [27]

[SUGESTÃO] Mensagem central do curso: "Comece com um agente. Só divida quando
houver partes independentes, um critério para verificar cada parte e um motivo
mensurável (qualidade, tempo ou contexto) que compense o custo extra."

[SUGESTÃO] Ciclo observável que atravessa Essentials e Hands On:
OBJETIVO → DECOMPOR → PAPÉIS → CONTRATOS (entrada/saída) → PERMISSÕES E LIMITES
→ CRITÉRIO DE PARADA → EXECUTAR E ACOMPANHAR → AVALIAR POR ETAPA E PONTA A PONTA
→ COMPARAR COM AGENTE ÚNICO → REGISTRAR E AJUSTAR.

[SUGESTÃO] Divisão de profundidade: Essentials usa n8n Cloud (visual, sem
programar) e demonstrações do Claude Code pelo app desktop; Hands On executa as
quatro oficinas em Claude Code (subagentes em arquivo .md) e n8n (orquestrador +
especialistas + revisão humana + avaliação).

1.1 O que é "multiagente" neste curso

[CONFIRMADO] O n8n define sistema multiagente (MAS) como um conjunto de agentes
de IA autônomos que interagem num ambiente compartilhado, cada um especializado,
e aponta três acréscimos em relação a um agente único: comunicação entre agentes,
memória compartilhada e lógica de orquestração. [19]

[CONFIRMADO] A Anthropic descreve o padrão orquestrador-trabalhadores: "um LLM
central divide dinamicamente a tarefa, delega subtarefas a LLMs trabalhadores e
sintetiza os resultados"; serve quando não é possível prever as subtarefas. [10]

[SUGESTÃO] Definição para leigos: "Multiagente é dividir um trabalho grande entre
vários assistentes de IA com funções diferentes, cada um com instruções,
ferramentas e limites próprios, e ter alguém (um agente coordenador, um fluxo
fixo ou uma pessoa) que distribui as tarefas, junta os resultados e confere."

3. PRIMEIROS PASSOS (NOMES EXATOS DA INTERFACE)
================================================================

3.1 Claude Code — primeiro subagente (sem programar)

Passo a passo (ajuda en) [1][7]:
1. Instalar e abrir um terminal na pasta do projeto, ou usar o app Desktop.
2. Rodar: claude  → seguir o login no navegador com conta Pro ou superior.
3. Conferir instalação: claude --version (deve imprimir algo como
   "2.1.xxx (Claude Code)"); diagnóstico: claude doctor.
4. Pedir em linguagem natural, por exemplo:
   "Crie um subagente de projeto chamado revisor-de-texto em .claude/agents/.
   Ele deve ser somente leitura, usar Sonnet e revisar clareza e coerência."
5. Abrir e revisar o arquivo gerado (.claude/agents/revisor-de-texto.md).
6. Invocar: "Use o subagente revisor-de-texto para revisar o README" ou com
   @-menção: @"revisor-de-texto (agent)" ou @agent-revisor-de-texto.
7. Acompanhar: /tasks lista o que está em segundo plano; Ctrl+B manda uma tarefa
   em execução para segundo plano; Esc nega uma chamada de ferramenta sem parar o
   subagente.

[CONFIRMADO] Sinal de êxito: o subagente aparece no painel abaixo do campo de
mensagem enquanto roda e devolve um resumo à conversa principal. [1]

[CONFIRMADO] Erro comum: se a pasta ~/.claude/agents/ não existia quando a sessão
começou, o Claude não encontra o novo subagente; é preciso reiniciar o Claude
Code. Arquivos sem name, com "---" fora da primeira linha, com ":" no nome ou sem
description são ignorados em silêncio; usar claude --debug para ver o motivo.
[1]

Formato mínimo do arquivo (ajuda en) [1]:
---
name: revisor-de-texto
description: Revisa textos quanto a clareza e coerência. Use após redigir.
tools: Read, Glob, Grep
model: sonnet
---
Você é um revisor. Aponte problemas de clareza, coerência e termos sem definição,
em lista numerada com trecho, problema e sugestão. Não edite arquivos.

3.2 Claude Code — primeira equipe de agentes (experimental)

Passo a passo (ajuda en) [2]:
1. Ligar o recurso em settings.json:
   { "env": { "CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS": "1" } }
2. Em sessão interativa, pedir: "Spawn three teammates to explore this from
   different angles: one on UX, one on technical architecture, one playing
   devil's advocate." (exemplo oficial; pode ser pedido em português).
3. O líder cria a lista de tarefas compartilhada e os colegas (teammates).
4. Navegar no painel de agentes: setas para cima/baixo selecionam um colega;
   Enter abre a transcrição e permite enviar mensagem direta; Esc limpa a seleção
   ou interrompe o turno do colega que está sendo visto; x para um colega
   selecionado; Ctrl+T mostra/oculta a lista de tarefas.
5. Encerrar: "Ask the researcher teammate to shut down".

[CONFIRMADO] Atenção: o Claude pode usar subagentes em vez de equipe; o painel
sozinho não confirma que uma equipe se formou. Se isso ocorrer, pedir
explicitamente "an agent team". [2]

[CONFIRMADO] Com equipes ligadas, um subagente que o Claude "nomeia" sai como
colega de equipe, e equipes podem se formar sem pedido; para voltar ao normal,
ajustar a variável para "0". [2]

3.3 Claude Code — primeiro workflow dinâmico

[CONFIRMADO] Passo a passo (ajuda en) [3]:
1. Rodar /deep-research <pergunta> (workflow embutido; exige WebSearch).
2. Aprovar: opções "Yes, run it", "Yes, and don't ask again for <name> in
   <path>" (só para workflows salvos/embutidos), "View raw script" e "No".
   No app Desktop o cartão tem Once, Always e Deny.
3. Acompanhar com /workflows: ↑/↓ seleciona fase ou agente; Enter detalha;
   f filtra; p pausa/retoma; x para; r reinicia agente; s salva o script.
4. Ler o relatório final, com fontes e alegações não confirmadas filtradas.
Para criar um workflow próprio: incluir a palavra ultracode no pedido ou escrever
"use a workflow". Para salvar: /workflows → selecionar execução → s.

3.4 n8n — primeiro orquestrador com dois especialistas (visual)

Passo a passo [SUGESTÃO] montado a partir de (ajuda en) [11][12][19][20]:
1. Criar workflow novo e adicionar o gatilho de chat ("When chat message
   received").
2. Adicionar o nó AI Agent (orquestrador). Conectar um Chat Model (sub-nó de
   modelo) e, se houver conversa de vários turnos, Simple Memory.
3. No conector Tools do AI Agent, adicionar dois nós AI Agent Tool:
   "Pesquisador" e "Redator". Em cada um preencher Description (quando o
   orquestrador deve chamá-lo), Prompt (User Message) e, em Options, System
   Message e Max Iterations. Cada AI Agent Tool precisa do próprio Chat Model.
4. Ligar "Require Specific Output Format" no Redator e conectar um parser de
   saída estruturada, se quiser JSON.
5. No System Message do orquestrador: quem são os especialistas, em que ordem
   usar, formato final e quando parar.
6. Abrir o chat, enviar um pedido e acompanhar a execução no canvas.
7. Conferir em Executions: abrir a execução, clicar no AI Agent e ver os passos
   intermediários (ligar "Return Intermediate Steps" ajuda). [37]

[CONFIRMADO] O AI Agent exige pelo menos uma ferramenta conectada. [11]
[CONFIRMADO] Em sub-nós, expressões sempre resolvem para o primeiro item de
entrada (ex.: {{ $json.name }}). [12][13]
[CONFIRMADO] "Uma descrição boa e específica diz ao agente pai quando delegar
tarefas a este agente." [12]

3.5 n8n — primeiro bloqueio humano

[CONFIRMADO] Passo a passo (ajuda en) [14]:
1. Clicar no conector Tools do AI Agent para abrir o painel de ferramentas.
2. Na seção Human review, escolher o canal de aprovação e configurar credencial.
3. Conectar as ferramentas que exigem aprovação ao conector de ferramentas do

4. Descrever no System Message quais ferramentas precisam de aprovação e o que

Canais: Chat do n8n, Slack, Discord, Telegram, Microsoft Teams, Gmail, WhatsApp
Business Cloud, Google Chat e Microsoft Outlook.
Sinal de êxito: o workflow pausa; o revisor vê qual ferramenta e com quais
parâmetros; Approve executa, Deny cancela e informa a IA.

4. GLOSSÁRIO PARA LEIGOS
================================================================

Agente: programa que recebe um objetivo, decide passos e usa ferramentas em ciclo
até concluir; checa o resultado real de cada ação. [10]
Agente único com ferramentas: um só agente que chama várias ferramentas (busca,
planilha, e-mail). Primeira opção a tentar. [10][20]
Sistema multiagente: vários agentes com papéis distintos coordenados para um
objetivo comum. [19]
Orquestrador / líder / supervisor: agente que divide o trabalho, distribui e junta
os resultados. No Claude Code, "team lead"; no n8n, o AI Agent raiz. [2][12]
Trabalhador / especialista / worker: agente que executa uma parte delimitada. [10]
Subagente: agente chamado por outro, com contexto próprio, que devolve só um
resumo. No Claude Code roda dentro de uma sessão. [1]
Colega de equipe (teammate): no Claude Code, sessão completa e independente que
conversa com as outras e com o líder. [2]
Agente como ferramenta (agent as tool): o agente principal chama o especialista
como se fosse uma ferramenta e continua dono da conversa. [12][28]
Handoff (passagem de bastão): o controle da conversa passa ao especialista, que
responde diretamente ao usuário. [28][29]
Roteador (router): passo que classifica a entrada e a envia ao especialista
certo; pode ser regra fixa (Switch) ou um LLM. [10][20][29]
Pipeline / encadeamento: etapas em ordem fixa; a saída de uma é a entrada da
próxima. [10]
Paralelização: várias partes ao mesmo tempo (seccionamento) ou a mesma tarefa
várias vezes para votar. [10]
Avaliador-otimizador / revisão / debate: um agente produz, outro critica, até
atingir o critério. [10][2]
Swarm (enxame): agentes que se coordenam entre pares, sem chefe fixo. O estudo do
Google chama de "decentralized" (malha ponto a ponto). [25]
Contexto / janela de contexto: tudo o que o modelo "vê" numa chamada. Cada
subagente ou colega tem a sua. [1][2]
Contrato de entrada e saída: acordo explícito do que cada agente recebe e devolve
(campos, formato, limites). [SUGESTÃO]
Artefato: arquivo ou documento produzido e passado adiante (relatório, planilha,
código). [SUGESTÃO]
Estado: o que já foi feito e decidido; inclui lista de tarefas e resultados
salvos. [2][3]
Memória: informação guardada entre turnos ou sessões (Simple Memory no n8n;
campo memory no Claude Code). [1][19]
Critério de parada: condição que encerra o trabalho (meta atingida, número máximo
de iterações, tempo, custo). [SUGESTÃO; base em 1][12][20]
Max Iterations / maxTurns: limite de ciclos de um agente no n8n e no Claude Code.
[1][12]
Human-in-the-loop / revisão humana: pausa para uma pessoa aprovar ou negar uma
ação. [14]
Permissão / menor privilégio: dar a cada agente só as ferramentas necessárias.
[1][6]
Prompt injection: texto malicioso que tenta mudar as instruções do agente. [6]
Token: unidade de texto que o modelo lê e escreve; base do custo. [5]
Observabilidade: capacidade de ver o que cada agente fez, quanto custou e quanto
demorou. [5][17][20]
Rastreamento (tracing): registro encadeado de cada passo de uma execução. [17]
Avaliação (eval): rodar casos de teste com resultado esperado e medir. [15]
LLM como juiz: um modelo dá nota à resposta de outro usando uma rubrica. [9][15]
Worktree: cópia isolada do repositório Git para um agente editar sem conflito.
[1][4]

5. FUNCIONALIDADES, LOCALIZAÇÃO, PLANO, LIMITES E DEPENDÊNCIAS

5.1 Claude Code — subagentes

[CONFIRMADO] Cada subagente roda na própria janela de contexto, com prompt de
sistema, ferramentas e permissões próprios, e devolve só o resumo. Suas
requisições contam nos mesmos limites de uso da conversa principal. [1]

[CONFIRMADO] Subagentes embutidos: Explore (somente leitura, busca rápida),
Plan (somente leitura, pesquisa no modo de planejamento), General-purpose
(todas as ferramentas), statusline-setup (Sonnet) e claude-code-guide (Haiku).
[1]

[CONFIRMADO] Onde ficam e prioridade (maior primeiro): configurações gerenciadas
da organização; flag --agents; .claude/agents/ do projeto; ~/.claude/agents/ do
usuário; pasta agents/ de plugin. Em nomes iguais, vence a de maior prioridade.
[1]

[CONFIRMADO] Campos do cabeçalho (só name e description são obrigatórios): tools
(lista permitida), disallowedTools (lista negada), model (sonnet, opus, haiku,
fable, ID completo ou inherit), permissionMode, maxTurns, autoCompactWindow,
skills, mcpServers, hooks, memory (user, project ou local), background,
omitClaudeMd, effort, isolation (worktree), color, initialPrompt. [1]

[CONFIRMADO] Modos de permissão: default/manual (pergunta), acceptEdits, auto
(classificador revisa), dontAsk (nega o que perguntaria), bypassPermissions e
plan (somente leitura). Se a conversa principal estiver em bypassPermissions,
acceptEdits ou auto, o subagente herda e ignora o próprio permissionMode. [1]

[CONFIRMADO] Ferramentas sempre retiradas de subagentes: AskUserQuestion,
EnterPlanMode, ExitPlanMode (exceto em plan), ScheduleWakeup, entre outras. Ou
seja, um subagente não pode fazer perguntas ao usuário. [1]

[CONFIRMADO] Subagentes não veem o histórico da conversa nem arquivos já lidos;
recebem a mensagem de delegação, o próprio prompt, CLAUDE.md (salvo omissão) e
um retrato do git status. Explore e Plan não carregam CLAUDE.md. [1]

[CONFIRMADO] Primeiro plano e segundo plano: em primeiro plano o subagente
bloqueia a conversa; em segundo plano roda em paralelo e os pedidos de permissão
aparecem na sessão principal com o nome do subagente. Por padrão, subagentes
criados pelo Claude começam em segundo plano. [1]

[CONFIRMADO] Retomar: cada chamada cria instância nova; para continuar, pedir ao
Claude que retome (ele usa SendMessage com o ID ou nome). Explore e Plan não podem
ser retomados. Transcrições ficam em
~/.claude/projects/{projeto}/{sessão}/subagents/agent-{id}.jsonl e são apagadas
após 30 dias por padrão. [1]

[CONFIRMADO] Memória persistente: user em ~/.claude/agent-memory/<agente>/;
project em .claude/agent-memory/<agente>/ (padrão recomendado); local em
.claude/agent-memory-local/<agente>/. As primeiras 200 linhas ou 25 KB do
MEMORY.md entram no prompt. [1]

[CONFIRMADO] Hooks específicos: PreToolUse e PostToolUse no cabeçalho do
subagente; SubagentStart e SubagentStop em settings.json, com filtro pelo nome do
agente. Exemplo oficial: hook que bloqueia INSERT/UPDATE/DELETE de um subagente
leitor de banco (código de saída 2 bloqueia). [1]

[CONFIRMADO] Plugins não podem definir hooks, mcpServers nem permissionMode em
subagentes, por segurança. [1]

5.2 Claude Code — agent teams

[CONFIRMADO] Componentes: team lead (sessão principal), teammates (instâncias
separadas), task list (lista compartilhada) e mailbox (mensagens). Tarefas têm
três estados: pending, in progress e completed; podem depender de outras e
aparecem bloqueadas até elas terminarem. A reivindicação usa trava de arquivo
para evitar disputa. [2]

[CONFIRMADO] Diferenças em relação a subagentes: [2]
- Contexto: ambos têm janela própria; colegas são totalmente independentes.
- Comunicação: subagentes devolvem ao chamador; colegas falam entre si.
- Coordenação: no subagente, o principal gerencia tudo; na equipe, há
  auto-coordenação por mensagens e lista de tarefas.
- Melhor para: tarefa focada em que só o resultado importa vs. trabalho que exige
  discussão e colaboração.
- Custo: menor vs. maior (cada colega é uma instância separada).

[CONFIRMADO] Modos de exibição: in-process (qualquer terminal) e split panes
(exige tmux ou iTerm2; configurar teammateMode "auto"). [2]

[CONFIRMADO] Planejar antes de implementar: com o líder em plan mode, o colega
criado também planeja e envia pedido de aprovação ao líder; se o modo do colega
não foi alterado, o Claude Code aprova o plano automaticamente, sem revisão do
líder. [2]

[CONFIRMADO] Permissões: não é possível definir modo por colega ao criá-lo; o
colega começa no modo do líder, inclusive bypassPermissions. Pedidos de permissão
dos colegas aparecem na sessão do líder. Uma mensagem de outro agente é marcada
como vinda de outra sessão do Claude, não do usuário; um colega não pode aprovar
permissão nem dar consentimento pelo usuário. [2]

[CONFIRMADO] Portões de qualidade por hooks: TeammateIdle, TaskCreated e
TaskCompleted; sair com código 2 impede a ação e devolve feedback. [2]

[CONFIRMADO] Limitações: /resume e /rewind não restauram colegas in-process;
status de tarefa pode atrasar; desligamento pode ser lento; uma equipe por
sessão; sem equipes aninhadas; o líder é fixo; sem modo de permissão por colega
na criação; split panes exige tmux ou iTerm2. [2]

[CONFIRMADO] Tamanho recomendado: começar com 3 a 5 colegas; 5 a 6 tarefas por
colega; "três colegas focados frequentemente superam cinco dispersos". [2]

5.3 Claude Code — dynamic workflows

[CONFIRMADO] Um workflow dinâmico é um script JavaScript que orquestra muitos
subagentes; o Claude escreve o script e um runtime o executa em segundo plano.
Funções: agent() cria um subagente, pipeline() roda um por item de lista,
parallel() roda vários ao mesmo tempo, phase() agrupa e log() registra. Um
schema faz o subagente devolver JSON validado (até cinco tentativas). [3]

[CONFIRMADO] Quem decide o próximo passo: em subagentes e equipes, o Claude turno a
turno; no workflow, o script. Resultados intermediários ficam em variáveis do
script, não no contexto do Claude. Execução retomável na mesma sessão. [3]

[CONFIRMADO] Não aceita entrada do usuário no meio da execução; para aprovação
entre etapas, rodar cada etapa como workflow separado. [3]

[CONFIRMADO] Salvar para reutilizar: .claude/workflows/ (projeto, compartilhado no
repositório) ou ~/.claude/workflows/ (pessoal); vira o comando /<nome>. [3]

5.4 n8n — peças para multiagentes

[CONFIRMADO] AI Agent: conecta um modelo de chat a ferramentas; o agente decide
quais chamar. Exige pelo menos uma ferramenta. [11]

[CONFIRMADO] AI Agent Tool: permite que um agente raiz chame outros agentes como
ferramentas; pode ser aninhado em várias camadas. Parâmetros: Description,
Prompt (User Message), Require Specific Output Format, Enable Fallback Model.
Opções: System Message, Max Iterations, Return Intermediate Steps,
Automatically Passthrough Binary Images, Batch Processing (Batch Size e Delay
Between Batches). [12]

[CONFIRMADO] Call n8n Workflow Tool: o agente roda outro workflow e recebe a
saída. Source: Database (escolher workflow ou ID) ou Define Below (colar JSON).
Workflow Inputs aparecem após definir o schema de entrada no sub-workflow e
clicar em Refresh; cada entrada aceita valor fixo, expressão, valor definido pela
IA ("Let the model define this parameter") ou $fromAI(). Em produção, o
sub-workflow precisa estar publicado; senão, erro "Workflow is not active and
cannot be executed". [13]

[CONFIRMADO] Quando usar cada um: AI Agent Tool para "delegação dinâmica, em que o
orquestrador precisa decidir em tempo de execução qual especialista acionar";
sub-workflows para "pipelines previsíveis em que você conhece a sequência", para
reutilização e teste independente. Separar sub-workflows quando a lógica se
repete, o canvas passa de 15–20 nós ou partes precisam de teste isolado. [20]

[CONFIRMADO] Execução: sistemas multiagente no n8n rodam em sequência por padrão;
paralelismo é opcional (Execute sub-workflow, HTTP Request com várias requisições
ou nó LangChain Code). [19]

[CONFIRMADO] Memória: Simple (janela), em banco (Postgres, Redis, MongoDB) e
estratégias de session ID (compartilhada, isolada ou por usuário). Para passagem
eficiente, guardar resultados intermediários em memória compartilhada (nó Memory
Manager) e passar IDs ou URLs em vez do conteúdo completo. [19][20]

[CONFIRMADO] Roteamento: Switch para categoria conhecida; IF para portões de
qualidade (aprovar ou devolver o rascunho). [20]

[CONFIRMADO] Revisão humana por ferramenta (2.6+), inclusive dentro de subagentes:
"Human review steps in sub-agents work correctly when an AI Agent is used as a
tool for another agent." Variáveis: $tool.name e $tool.parameters. [14][17]

[CONFIRMADO] Avaliações: light (comparar saídas com casos conhecidos durante o
desenvolvimento) e com métricas. Métricas embutidas da operação Set Metrics:
Correctness (IA, 1–5), Helpfulness (IA, 1–5), String Similarity (0–1),
Categorization (0 ou 1) e Tools Used (0–1); métricas personalizadas são sempre
números. Operação "Check if evaluating" evita custo de métrica em produção.
Rodar em Evaluations tab → Run Test. Datasets em data tables ou Google Sheets.
[15]

[CONFIRMADO] Agents (Preview, 2.40): construtor com abas Agent, Instructions,
Tools, Capabilities, Skills, Knowledge, Memory, Agents (subagentes), Channels
(Slack, Telegram, Linear, Microsoft Teams), Schedules e Sessions; nó Message an
Agent e Message an Agent Tool para usar agentes dentro de workflows; aprovação
para chamadas sensíveis. [16]

7. BOAS PRÁTICAS E EXEMPLOS OFICIAIS

7.1 Decidir se vale dividir

[CONFIRMADO] Anthropic: começar simples e acrescentar complexidade "só quando
demonstravelmente melhora os resultados". [10]
[CONFIRMADO] Claude Code: antes de montar equipe, verificar se uma opção mais leve
resolve; equipes funcionam melhor quando os colegas operam de forma
independente; para tarefas sequenciais, edições no mesmo arquivo ou muitas
dependências, sessão única ou subagentes são mais eficazes. [2]
[CONFIRMADO] n8n: "Não use um agente para trabalho que um nó simples faz melhor";
evitar multiagente em tarefas simples em que a coordenação custa mais que o
benefício. [19][20]
[CONFIRMADO] Google: o desempenho depende das propriedades da tarefa
(decomponibilidade, número de ferramentas); o modelo preditivo acertou a melhor
estratégia em 87% das configurações não vistas. [25]

[SUGESTÃO] Checklist "dividir ou não dividir" (5 perguntas):
1. As partes podem andar sem esperar umas pelas outras?
2. Cada parte tem entrada e saída claras e verificáveis?
3. Um agente único está estourando contexto ou escolhendo mal entre muitas
   ferramentas?
4. O ganho esperado (qualidade, tempo) compensa 4–15x mais tokens?
5. Existe um jeito de medir se ficou melhor que o agente único?
Se houver menos de 3 "sim", ficar com agente único.

7.2 Escrever papéis e delegações

[CONFIRMADO] Anthropic Research: dar a cada subagente objetivo claro, formato de
saída, orientação de ferramentas e limites da tarefa para evitar duplicidade;
regras de escala de esforço (fato simples: 1 agente e 3–10 chamadas de
ferramenta); começar amplo e depois estreitar; reescrever descrições ruins de
ferramentas reduziu em 40% o tempo de conclusão. [9]
[CONFIRMADO] Claude Code: description curta para o Claude delegar bem; detalhes no
corpo do prompt; ferramentas no mínimo necessário; Haiku para tarefas simples e
volumosas; repetir regras do projeto no pedido de delegação se o subagente não ler
CLAUDE.md. [1]
[CONFIRMADO] Equipes: dar contexto suficiente no prompt de criação (exemplo
oficial descreve pasta, foco, tecnologia e formato com severidade). [2]
[CONFIRMADO] n8n: incluir no System Message a configuração de ferramentas e de
revisão humana; descrições de ferramentas guiam o roteamento. [14][20]

Modelo de cartão de papel [SUGESTÃO]:

8. SEGURANÇA, PRIVACIDADE, DADOS, CREDENCIAIS E LGPD
================================================================

8.1 Modelo de ameaça para leigos [SUGESTÃO com base em 27]
Mais agentes = mais portas. Cada agente lê conteúdo, tem ferramentas e passa
mensagens. Um texto malicioso lido por um agente pode virar instrução para o
próximo; um erro de um agente pode ser tratado como fato pelos outros.

8.2 Riscos catalogados (OWASP Agentic Top 10, 2026) [27]
[CONFIRMADO] ASI01 Agent Goal Hijack (conteúdo malicioso altera objetivos);
ASI02–ASI06 cobrem uso indevido de ferramentas, abuso de identidade e privilégio,
cadeia de suprimentos, execução de código e envenenamento de memória; ASI07
Insecure Inter-Agent Communication (mensagens sem autenticação permitem
falsificação ou injeção); ASI08 Cascading Failures (erro de um agente se propaga);
ASI09 Human-Agent Trust Exploitation; ASI10 Rogue Agents (agentes comprometidos
agindo fora do escopo). Princípios: Least Agency e Strong Observability.
[VERIFICAR] Nomes exatos de ASI02–ASI06 vieram de fontes secundárias; conferir no
PDF oficial (seção 16).

8.3 Controles no Claude Code
[CONFIRMADO] Menor privilégio por subagente: tools, disallowedTools, mcpServers
próprios, permissionMode e hooks PreToolUse para validar comandos. [1]
[CONFIRMADO] Mensagens entre agentes são marcadas como vindas de outra sessão; um
colega negado não pode repassar a ação a outro colega para burlar a checagem; no
modo auto, o classificador trata alegação de aprovação vinda de outro agente como
entrada não confiável. [2]
[CONFIRMADO] Relatórios finais de subagentes são verificados contra imitação de
tags de sistema ou texto de permissão; a verificação marca, não remove, e não
substitui as permissões. [1]
[CONFIRMADO] Proteções gerais: aprovação de comandos de rede (curl, wget) no modo
Manual; sandbox de Bash com isolamento de arquivos e rede (não suportado no
Windows nativo; suportado no WSL 2); diálogo de confiança na pasta; boas práticas
com conteúdo não confiável: revisar comandos, não "despejar" conteúdo não
confiável, verificar mudanças em arquivos críticos, usar VMs. "Nenhum sistema é
completamente imune." [6][7]
[CONFIRMADO] Atenção: colegas de equipe herdam o modo do líder, inclusive
bypassPermissions. [2]
[CONFIRMADO] Arquivos de agente de projeto com hooks ou servidores MCP inline
exigem confiança na pasta. [1]

8.4 Controles no n8n
[CONFIRMADO] Revisão humana é bloqueio real na ferramenta, não instrução de prompt:
a ferramenta não executa sem aprovação; recomendada para ações irreversíveis
(apagar dados, enviar comunicação externa, compras), exigência de conformidade ou
alto impacto; começar com revisão ligada e reduzir com a confiança. [14]
[CONFIRMADO] 2.30: aprovações registram identidade do aprovador e horário. 2.44
(Enterprise): políticas de tipo de nó checadas também no uso de ferramentas por
agentes. [17]
[CONFIRMADO] Isolar falhas: cada agente ou sub-workflow com tratamento de erro
próprio; erros estruturados com campo success; timeouts explícitos (~30 s como
ponto de partida). [20]

8.5 Dados, credenciais e LGPD [SUGESTÃO, salvo marcações]
- Nunca colar chaves de API em prompts; no n8n usar Credentials; no Claude Code,
  credenciais ficam no Keychain (macOS), arquivo 0600 (Linux) ou perfil do
  usuário (Windows). [CONFIRMADO 6]
- Cada agente extra é mais um ponto que lê dados pessoais: minimizar o que é
  passado entre agentes (IDs no lugar do conteúdo [CONFIRMADO 19]).
- Usar dados fictícios ou anonimizados nas oficinas (datasets da seção 12).
- Ao enviar dados pessoais a provedores de LLM, verificar base legal, contrato e
  transferência internacional (LGPD, arts. 7º e 33) com o encarregado da
  organização.
- Termos: planos Free/Pro/Max/Ultra seguem Consumer Terms; Team/Enterprise/API
  seguem Commercial Terms; usuário consumidor pode mudar preferência de uso para
  treino em claude.ai/settings/privacy. [CONFIRMADO 6]

9. LIMITAÇÕES, ERROS, OBSERVABILIDADE, RECUPERAÇÃO E CUSTOS
================================================================

9.1 Por que sistemas multiagente falham
[CONFIRMADO] MAST: 14 modos em 3 grupos — especificação (papéis e tarefas mal
definidos), desalinhamento entre agentes (informação retida, conversa
desviada, ignorar o outro) e verificação/término (parar cedo, não verificar,
verificar errado). Base: 7 frameworks, 200+ tarefas, 1.600+ traços anotados;
concordância humana κ = 0,88. [26]
[VERIFICAR] Lista nominal dos 14 modos: conferir no PDF arXiv 2503.13657.
[CONFIRMADO] Google: independentes amplificam erro 17,2x; centralizados 4,4x;
quanto mais ferramentas, maior o custo de coordenação. [25]
[CONFIRMADO] Cognition: subagentes fazem suposições conflitantes que o agente final
precisa conciliar; "ações carregam decisões implícitas". [24]

9.2 Erros frequentes e recuperação (Claude Code)
- Subagente não aparece → reiniciar se a pasta foi criada depois; claude --debug
  para arquivos ignorados; /doctor para nomes duplicados. [1]
- "Concurrent subagent limit reached" → esperar ou ajustar
  CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS. [1]
- maxTurns atingido → saída marcada como parcial; pode ser retomada. [1]
- Colegas não aparecem → selecionar no painel; linhas ociosas somem após 30 s;
  conferir se a tarefa justificava equipe; para split panes, which tmux. [2]
- Claude cria colegas em vez de subagentes → variável de equipes = "0". [2]
- Muitos pedidos de permissão → pré-aprovar comandos comuns antes de criar
  colegas. [2]
- Agentes param cedo → abrir a transcrição e dar instruções ou criar substituto;
  o líder também pode encerrar antes; mandar continuar. [2]
- Tarefa travada → verificar se o trabalho está feito e atualizar o status. [2]
- Sessões tmux órfãs → tmux ls; tmux kill-session -t <nome>. [2]
- Workflow com agente travado → reinício automático até 5 vezes; mensagens
  "agent stalled on all 6 attempts" etc.; aumentar stallMs. [3]
- Workflow parado → relançar; agentes concluídos devolvem resultado salvo, os
  posteriores a uma falha rodam de novo. [3]
- Limite de uso atingido → workflow pausa e retoma após o reset (condições na
  documentação). [3]

9.3 Erros frequentes e recuperação (n8n)
- Ferramenta de sub-workflow falha sem motivo claro → publicar o sub-workflow;
  ver a lista de execuções dele. [13]
- Expressão pega o item errado → em sub-nós a expressão usa o primeiro item. [12]
- Agente em loop → Max Iterations e limite de 2–3 rodadas em ciclos de
  autocorreção. [12][20]
- Roteamento errado → melhorar Description de cada AI Agent Tool; trocar por
  Switch quando a categoria for previsível. [12][20]
- Erros de limite de taxa do provedor na avaliação → reduzir a concorrência. [15]
- Modelo indisponível → Enable Fallback Model. [12]
- Contagem de tokens inconsistente no AI Agent com Return Intermediate Steps →
  relatado na comunidade. [VERIFICAR 37]

9.4 Observabilidade
[CONFIRMADO] Claude Code: /usage mostra custo da sessão (para API) e, nos planos
por assinatura, atribuição de uso a subagentes, skills e MCP; /tasks lista o que
roda em segundo plano; /workflows mostra tokens por agente; transcrições .jsonl
por subagente; OpenTelemetry para métricas por usuário. [1][3][5]
[CONFIRMADO] n8n: cada execução grava entrada e saída de cada nó; Insights por
plano (Starter só banner; Pro 7–14 dias; Enterprise 365 dias); OpenTelemetry para
execuções (2.15) e agentes (2.20, atributos personalizados Enterprise); LangSmith
e OpenTelemetry em self-hosted. [17][18][37]
[CONFIRMADO] n8n recomenda acompanhar tokens por execução, por agente e por
chamada de ferramenta e criar alertas para consumo anormal. [20]

9.5 Custos
[CONFIRMADO] Agentes ~4x tokens de um chat; multiagente ~15x (Anthropic). [9]
[CONFIRMADO] Multiagente "10–20x" os tokens de agente único (n8n). [20]
[CONFIRMADO] Equipes no Claude Code: cerca de 7x mais tokens que sessões padrão
quando os colegas rodam em plan mode; custo cresce de forma aproximadamente
linear com o número de colegas; usar Sonnet nos colegas, equipes pequenas,
prompts focados e desligar colegas ao terminar. [5]
[CONFIRMADO] Cache de prompt de colegas e agentes de workflow dura 5 minutos por
padrão (configurável para 1 h, com escrita mais cara). [2][3]
[CONFIRMADO] Workflows: testar numa fatia pequena antes (uma pasta, uma pergunta
estreita). [3]
[SUGESTÃO] Fórmula didática: custo ≈ (nº de agentes) × (contexto médio por
chamada) × (nº de chamadas) × (preço do modelo). Reduzir qualquer fator reduz o
custo; o mais barato costuma ser "menos agentes" e "modelo menor nos
especialistas".

10. COMPARAÇÃO IMPARCIAL COM ALTERNATIVAS

10.1 Claude Code x n8n (para este curso) [SUGESTÃO]
- Claude Code: melhor para trabalho em arquivos e código, pesquisa e revisão;
  papéis em arquivos .md versionáveis; permissões finas; exige plano pago e
  conforto mínimo com terminal (ou app Desktop).
- n8n: melhor para processos de negócio com integrações (e-mail, Slack, planilhas),
  visual, com revisão humana por ferramenta e avaliação embutida; exige credencial
  de LLM e conta n8n.

10.2 Frameworks de referência (só para explicar padrões)
[CONFIRMADO] OpenAI Agents SDK: orquestração guiada por LLM ou por código;
"agents as tools" (gerente mantém a conversa) e "handoffs" (especialista assume a
resposta); podem ser combinados. [28]
[CONFIRMADO] LangChain/LangGraph: padrões Subagents (supervisor), Handoffs,
Skills, Router e Custom workflow. Em pedido de um domínio, subagentes fazem 4
chamadas e os demais 3; em pedido repetido, padrões com estado (Handoffs, Skills)
economizam 40–50% de chamadas; em pedido multidomínio, Subagents e Router gastam
~9 mil tokens contra 14 mil+ de Handoffs. Observa que um agente único bem
equipado frequentemente faz trabalho semelhante. [29]
[VERIFICAR] CrewAI, AutoGen/Microsoft Agent Framework, Google ADK e plataformas
no-code (Make, Zapier Agents) também oferecem multiagente; não foram verificados
nesta pesquisa por estarem fora das ferramentas-âncora.

10.3 Agente único x equipe — evidências
[CONFIRMADO] A favor de equipe: tarefas amplas, paralelizáveis e que excedem uma
janela de contexto (pesquisa: +90,2%; finanças: +80,9% centralizado). [9][25]
[CONFIRMADO] A favor de agente único: tarefas sequenciais (−39% a −70%),
programação com contexto compartilhado, muitas dependências; custos 4–20x
maiores. [9][20][24][25]

13. EXERCÍCIOS
================================================================

Todos os exercícios são [SUGESTÃO] da pesquisa, montados sobre recursos
[CONFIRMADO] das seções 3, 5 e 7. Custos estimados são ordem de grandeza e
devem ser medidos com /usage (Claude Code) ou com o painel do provedor de LLM
(n8n) antes da gravação.

13a. EXERCÍCIOS CURTOS (um por ação da tarefa observável)

A1. DECOMPOR UM OBJETIVO (Essentials, sem ferramenta, 8 min)
Entrada: objetivo "Preparar um comparativo de 3 ferramentas de automação para a
diretoria".
Passos: listar subtarefas; marcar quais dependem de outras; marcar quais podem
rodar em paralelo; aplicar o checklist 7.1.
Resultado verificável: diagrama de 4–6 caixas com setas de dependência;
justificativa de "dividir" ou "não dividir".
Erro típico: dividir em etapas que dependem umas das outras (pipeline
disfarçado de paralelo).

A2. ATRIBUIR PAPÉIS (Essentials, 8 min)
Preencher 3 cartões de papel (modelo 7.2): Pesquisador, Analista, Revisor.
Verificação: nenhum papel se sobrepõe; cada um tem "PROIBIDO" e "PARA QUANDO".

A3. DEFINIR ENTRADAS E SAÍDAS (Essentials, 10 min)
Escrever o contrato JSON do Pesquisador:
{"ferramenta": "...", "preco_mensal": "...", "moeda": "...", "fonte_url": "...",
 "data_consulta": "AAAA-MM-DD", "confianca": "alta|media|baixa"}
Verificação: o Analista consegue trabalhar só com esses campos.

A4. CRITÉRIO DE PARADA (Essentials, 5 min)
Escrever para cada papel: meta (ex.: 3 fontes oficiais), teto (Max Iterations =
5 no n8n; maxTurns = 15 no Claude Code) e o que fazer ao bater o teto.

A5. COORDENAR A EXECUÇÃO (Hands On, Claude Code, 10 min)
Pedir: "Pesquise em paralelo, com subagentes separados, os arquivos README, docs/
e testes deste repositório e devolva um resumo de 5 linhas de cada."
Acompanhar em /tasks; mandar um subagente para segundo plano com Ctrl+B.
Êxito: três resumos retornam à conversa principal sem os conteúdos brutos.
Custo: baixo (leitura de poucos arquivos). [1]

A6. AVALIAR O RESULTADO (Hands On, n8n, 10 min)
Criar data table com 5 perguntas e respostas de referência; rodar Evaluations →
Run Test com a métrica Categorization ou Correctness. [15]
Êxito: nota por caso e média visíveis na aba Evaluations.

A7. SEGURANÇA — MENOR PRIVILÉGIO (Hands On, Claude Code, 8 min)
Criar subagente "auditor" com tools: Read, Grep, Glob; pedir que "corrija" um
arquivo. Êxito: ele não consegue editar e relata isso. [1]

A8. ESCALONAMENTO HUMANO (Hands On, n8n, 8 min)
Colocar a ferramenta "Enviar e-mail" (Gmail) atrás de Human review no Chat do n8n;
pedir ao agente que envie; negar. Êxito: o e-mail não sai e o agente explica a
negação. [14]

A9. COMPARAR COM AGENTE ÚNICO (Hands On, 10 min)
Mesmo pedido de A5 numa sessão sem subagentes; anotar tempo, tokens (/usage) e
qualidade. Êxito: tabela com as três medidas.

13b. OFICINAS (Hands On: 4 oficinas)

OFICINA 1 — Claude Code: revisão paralela com subagentes (15–20 min)
Material: Gilded Rose Refactoring Kata (versão Python ou JavaScript). [32]
Objetivo: três revisores com lentes distintas e um sintetizador humano.
Passos:
1. Clonar ou baixar o ZIP do repositório; abrir a pasta da linguagem escolhida.
2. Criar em .claude/agents/ três arquivos: revisor-requisitos (compara código com
   GildedRoseRequirements.txt), revisor-testes (aponta regras sem teste) e
   revisor-legibilidade. Todos com tools: Read, Grep, Glob e model: sonnet.
3. Pedir: "Use os três revisores em paralelo e devolva uma tabela única com
   achado, arquivo, regra do requisito e severidade."
4. Conferir cada achado no arquivo de requisitos.
Resultado verificável: os requisitos do kata (ex.: "Sulfuras" nunca muda;
"Aged Brie" aumenta de qualidade; qualidade nunca passa de 50) aparecem como
cobertos ou não. Gabarito: o próprio arquivo de requisitos.
Erros e recuperação: subagente não reconhecido → reiniciar sessão; revisores
repetem achados → afinar "MISSÃO" e "PROIBIDO" nos cartões.
Custo: baixo a moderado (3 subagentes lendo poucos arquivos).

OFICINA 2 — Claude Code: equipe com hipóteses concorrentes OU workflow (20 min)
Opção A (equipes experimentais): ligar CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1 e
pedir 3 colegas: implementador (só gilded_rose.*), testador (só arquivo de
teste), revisor (sem edição). Regra: cada colega dono de arquivos diferentes. [2]
Opção B (estável): "use a workflow to run the tests and keep fixing the reported
errors until they pass or two rounds in a row make no progress" (adaptar). [3]
Resultado verificável: testes passam; lista de tarefas toda em completed (A) ou
relatório do workflow (B).
Erros: dois colegas no mesmo arquivo → sobrescrita; líder implementando sozinho →
"Wait for your teammates to complete their tasks before proceeding". [2]
Custo: alto relativo (equipes ~7x tokens em plan mode); usar Sonnet; encerrar
colegas ao fim. [5]

OFICINA 3 — n8n: triagem de tickets com orquestrador e especialistas (20 min)
Material: bitext-amostra-oficina.csv (33 tickets, colunas instruction,
category, intent) importado numa data table. [33]
Passos:
1. Gatilho manual + leitura da data table.
2. AI Agent "Triagem" com três AI Agent Tool, agrupando as 11 categorias do
   dataset: "Financeiro" (INVOICE, PAYMENT, REFUND), "Pedidos e entregas"
   (ORDER, SHIPPING, DELIVERY, CANCEL) e "Conta e relacionamento" (ACCOUNT,
   SUBSCRIPTION, CONTACT, FEEDBACK), cada um com Description precisa e saída
   estruturada {categoria, resposta, precisa_humano}.
3. Variante determinística: Switch pela categoria prevista por um classificador
   simples; comparar.
4. Gravar categoria prevista na data table.
Resultado verificável: comparar categoria prevista com a coluna category
(gabarito do dataset); calcular acertos.
Erros: roteamento errado → reescrever Description; loop → Max Iterations.
Custo: baixo com modelo pequeno; 30 itens × 2–4 chamadas.

OFICINA 4 — n8n: revisão humana e avaliação ponta a ponta (20 min)
Passos:
1. No workflow da Oficina 3, adicionar ferramenta "Responder cliente" (Gmail ou
   Slack de teste) atrás de Human review. [14]
2. Escrever no System Message quando pedir aprovação e como reagir a Deny.
3. Montar avaliação: Evaluation Trigger lendo a data table; Set Outputs;
   Set Metrics com Categorization (acerto de rota) e Correctness (qualidade da
   resposta); Check if evaluating antes das métricas. [15]
4. Run Test duas vezes: versão multiagente e versão agente único (um AI Agent
   com instruções das três áreas).
Resultado verificável: duas linhas de resultado na aba Evaluations; nenhuma
mensagem sai sem aprovação.
Erros: limite de taxa → concorrência 1; métrica Correctness sem referência →
preencher coluna de resposta esperada.

14. RESPOSTAS AO FOCO ESPECÍFICO
================================================================

F1. Definição e diferenças
- Agente único com ferramentas: um ciclo de decisão; mais simples. [10]
- Subagentes: chamados por um agente, contexto próprio, devolvem resumo. [1]
- Handoff: o controle da conversa passa ao especialista. [28][29]
- Supervisor/worker: central divide, delega e sintetiza. [10][29]
- Roteador: classifica e envia; pode ser regra ou LLM. [10][20][29]
- Pipeline: ordem fixa de etapas. [10]
- Swarm: coordenação entre pares, sem chefe fixo (decentralized). [25]
Respondido em 1, 4 e 5.5.

F2. Quando ajudam e quando atrapalham
Ajudam em tarefas paralelizáveis, amplas, que excedem uma janela de contexto.
Atrapalham em tarefas sequenciais, código com contexto compartilhado e muitas
dependências; custo 4–20x. Evidências: Anthropic [9], Google [25], MAST [26],
Cognition [24], n8n [20]. Seções 0, 7.1, 9 e 10.3.

F3. Claude Code
Subagentes, equipes, workflows, agent view, projects: configuração, papéis
(arquivo .md), contexto, ferramentas, permissões, paralelismo, limites e
interface nas seções 2.1, 3.1–3.3 e 5.1–5.3. [1][2][3][4]

F4. n8n
AI Agent, AI Agent Tool, Call n8n Workflow Tool, memória, Switch/IF, Human review,
Evaluations e Agents (Preview) nas seções 3.4–3.6 e 5.4. Handoff nativo de
conversa: NÃO ENCONTRADO na documentação do n8n (busca em docs.n8n.io por
"handoff" em 18/11/2026); o blog diz que o padrão é passar contexto explícito
pelos parâmetros da ferramenta. [20]

F5. Padrões de coordenação e quando usar
- Sequencial (pipeline): etapas fixas e previsíveis. [10][20]
- Paralelo: partes independentes; velocidade ou foco. [10]
- Supervisor: subtarefas imprevisíveis; melhor contenção de erro (4,4x). [10][25]
- Debate/revisão: critérios claros; bugs com causa incerta. [2][10]
- Roteamento por especialidade: categorias distintas; Switch se previsível. [10][20]
- Escalonamento humano: ações irreversíveis, conformidade, alto impacto. [14]

F6. Contratos, contexto, memória, artefatos, estado, conclusão e loops
- Contratos: saída estruturada (Require Specific Output Format no n8n; schema em
  agent() no workflow). [3][12]
- Contexto: subagentes e colegas não herdam histórico; passar no prompt. [1][2]
- Memória: campo memory (Claude Code); Simple/DB memory e Memory Manager
  (n8n). [1][19][20]
- Artefatos: arquivos compartilhados; passar IDs/URLs. [19]
- Estado: lista de tarefas com dependências (equipes); variáveis do script
  (workflows); retomada. [2][3]
- Conclusão e loops: maxTurns, Max Iterations, teto de 2–3 rodadas, limite de
  1.000 agentes por workflow, condição "duas rodadas sem progresso". [1][3][12][20]

F7. Observabilidade
/usage, /tasks, /workflows, transcrições .jsonl, OpenTelemetry (Claude Code);
Executions, Return Intermediate Steps, Insights, OpenTelemetry, LangSmith (n8n);
versionar prompts e logar roteamento. Seção 9.4. [1][3][5][17][18][20]
Versão de prompts no Claude Code: arquivos .md em .claude/agents/ versionados no
Git [SUGESTÃO]; no n8n, version history do workflow e Git em Enterprise. [18]

F8. Segurança
Menor privilégio, segredos, isolamento (worktree, sandbox, VMs), prompt
injection, agente comprometido (ASI10), propagação de erro (ASI08), aprovação
humana. Seção 8. [1][2][6][14][27]

F9. Como testar

19.1 Claude Code — variáveis e configurações úteis [1][2][3][5]

- permissions.deny: "Agent(Explore)" bloqueia um tipo; "Agent" bloqueia todos

  (sessão iniciada com claude --agent) pode criar

  ~/.claude/teams/{time}/inboxes/{agente}.json; ~/.claude/tasks/{time}/

export const meta = { name: 'audit-routes', description: '...' }
const found = await agent('List every .ts file under src/routes/.', { schema: {...} })
const audits = await pipeline(found.files, f => agent(`Audit ${f}...`, { label: f }))
return audits.filter(Boolean)
Regras: meta como primeira instrução; Date.now() e Math.random() lançam erro
(para reprodutibilidade); sem import(); sem acesso direto a arquivos pelo script.
