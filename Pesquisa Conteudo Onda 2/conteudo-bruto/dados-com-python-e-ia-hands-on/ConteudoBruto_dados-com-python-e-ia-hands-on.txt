0. RESUMO EXECUTIVO
- O que é: o aluno descreve a análise em português, um agente de código (Claude Code ou Codex) escreve o script Python (pandas, Matplotlib), executa no computador do aluno ou na nuvem, e o aluno lê o código no nível de leigo, roda de novo do zero e confere os números contra uma fonte oficial. Diferença para o curso anterior (IA para Análise de Dados): aqui o resultado é um projeto reprodutível em pasta (script/notebook, dados brutos, resultados, registro de premissas), não só uma conversa.
- Para quem: analistas, financeiro/planejamento, pesquisadores, servidores e reguladores, engenheiros e técnicos que já fizeram IA para Análise de Dados - Essentials e não programam.
- O que mudou nos últimos 12 meses: (a) Claude Code passou a existir também no app de desktop (aba "Code") e na web, além do terminal e da extensão VS Code, e exige assinatura paga (Pro, Max, Ultra, Team ou Enterprise) ou conta de API [2][4][12]; (b) o "app Codex" foi incorporado ao app de desktop do ChatGPT: o Codex é escolhido no menu do ChatGPT, e fluxos de análise de dados migraram para o "ChatGPT Work" [13][23]; (c) Codex aparece no plano gratuito do ChatGPT ("Acesso limitado ao Codex"; modelo GPT-6 Luna no app de desktop, "subject to rollout") [14][19]; (d) a política "untrusted" de aprovação do Codex foi aposentada [15].
ALERTAS PARA QUEM VAI CRIAR O CURSO:
1) Não há caminho 100% gratuito com Claude Code (exige plano pago) [2][12]. O caminho gratuito é Codex no plano Free (limitado e "sujeito a lançamento gradual") ou Google Colab; o caminho mais estável para todos os exercícios é ChatGPT Plus (R$ 99,90/mês) ou Claude Pro (R$ 110/mês) [19][12].
2) Dados brasileiros quebram ferramentas: as bases públicas testadas usam latin-1, ";" e vírgula decimal; a ferramenta de edição de notebook do Claude Code "refuses a notebook file that doesn't decode as UTF-8" [7]. Ensinar a converter a cópia de trabalho para UTF-8 (sem tocar no bruto) é pré-requisito prático.
3) Agente de código age no computador: pode apagar e alterar arquivos e rodar comandos; incidentes reais em julho de 2025 (Replit apagou banco de produção; Gemini CLI perdeu arquivos de um usuário) [40]. O checkpoint do Claude Code não desfaz mudanças feitas por comandos Bash [11]. Trabalhar sempre numa cópia dos dados, com modo de permissão restrito e Git.
4) (Segunda rodada) Evidência independente forte para o eixo "validar": num estudo de 2026, 69,8% das execuções erradas de um agente de dados entregaram resultado com aparência normal, sem avisar [56]; os melhores sistemas acertam de 30,5% a 55% em benchmarks de análise com dados reais [54][37][55]; e só 24,11% de 863.878 notebooks do GitHub rodaram sem erro [61].

4. CONCEITOS E GLOSSÁRIO
(Definições e analogias são [SUGESTÃO] salvo indicação de fonte.)
- Agente de código: programa de IA que lê arquivos, escreve código e executa comandos no computador; "reads your codebase, edits files, runs commands" [3]. Analogia: um estagiário muito rápido que trabalha na sua mesa — precisa de instruções claras e de alguém conferindo.
- Terminal / linha de comando / shell: janela de texto onde se digitam comandos (PowerShell, CMD, Bash) [1]. Analogia: falar com o computador por bilhetes em vez de clicar.
- Python: linguagem em que o agente escreve a "receita" da análise.
- Script (.py): a receita inteira num arquivo; roda do começo ao fim. Notebook (.ipynb): caderno com células de código, texto e gráficos; "Jupyter notebook" [7][27]. Analogia: script = receita impressa; notebook = caderno de laboratório com anotações e fotos.
- Biblioteca/pacote: conjunto de ferramentas prontas que o script importa.
- pandas: biblioteca de tabelas (DataFrame) — "a planilha dentro do Python"; tutorial oficial "10 minutes to pandas" (inglês, link testado) [25]. NumPy: cálculos numéricos (base do pandas). Matplotlib: gráficos estáticos (tutoriais oficiais, link testado) [26]. seaborn: gráficos estatísticos sobre o Matplotlib. Plotly: gráficos interativos. openpyxl: ler/escrever .xlsx. Jupyter: notebooks [27].
- Ambiente virtual (.venv): uma "caixa" de bibliotecas só daquele projeto, para não misturar versões entre projetos.
- Gerenciador de pacotes (pip, uv): o "app store" das bibliotecas; o uv também instala o próprio Python [24].
- Arquivo de versões (requirements.txt, pyproject.toml, uv.lock): a "lista de compras" com versões exatas, para que outra pessoa monte o mesmo ambiente.
- Reprodutibilidade: "data and code available so the analysis can be fully rerun" (definição de The Turing Way, segundo resumo de busca) [28]. Analogia: outra cozinha, mesma receita, mesmo bolo.
- Semente aleatória (random seed): número que fixa sorteios para que se repitam iguais.
- Git / commit: "fotografias" numeradas do projeto; permite voltar atrás. O próprio Claude Code recomenda versionamento para desfazer o que comandos Bash alteraram [11].
- Assert (teste simples): linha de código que para o script se uma condição for falsa (ex.: "a soma tem de ser 203.080.756").
- Codificação (UTF-8 x latin-1): ver curso anterior; aqui é crítica porque ferramentas de edição recusam arquivos não UTF-8 [7].
- Modo de permissão (Claude Code): "default"/"Manual", "acceptEdits", "plan", "auto", "dontAsk", "bypassPermissions" [5]. Sandbox e política de aprovação (Codex): "Sandbox mode: What Codex can do technically..."; "Approval policy: When Codex must ask you before it executes an action" [15]. [CONFIRMADO]
- CLAUDE.md / AGENTS.md: arquivos de instruções persistentes do projeto lidos no início de cada sessão [9][16]. Analogia: o "manual do estagiário" colado na parede.
- Checkpoint / rewind: Claude Code "automatically tracks Claude's file edits"; "/rewind" ou "/undo" desfaz [11]. Worktree (Codex): cópia isolada do projeto via Git [17].
- Pacote alucinado / slopsquatting: a IA sugere instalar um pacote que não existe; um atacante pode registrar esse nome [39].

5. FUNCIONALIDADES
5.1 Claude Code (o que importa para dados)
- Ler, editar e criar arquivos; executar comandos (Bash/PowerShell) [3][5]. Planos: Pro e acima [12].
- Notebooks: leitura de .ipynb "return all cells with their outputs, including code, markdown, and visualizations"; erro se as células passarem de 256 KB ou o arquivo de 100 MB [7]. Edição com "NotebookEdit", uma célula por vez; ao trocar uma célula de código "its execution count and saved outputs are cleared. To get the output back, re-run the cell" [7][8]. "NotebookEdit refuses a notebook file that doesn't decode as UTF-8" [7]. No VS Code: "Save the notebook before you ask for an edit" [8]. [CONFIRMADO]
- Leitura de arquivos grandes: por padrão uma leitura retorna até 25.000 tokens e "refuses a whole file over 256 KB, so Claude reads a larger file in pages" [7]. Consequência [SUGESTÃO]: para bases grandes, o certo é o agente escrever código pandas que lê o arquivo, e não "ler" o CSV na conversa.
- Arquivos não UTF-8: Edit e NotebookEdit recusam "non-ASCII text saved in a legacy encoding such as Windows-1252" (trecho da referência de ferramentas) [7]. [CONFIRMADO — transcrição parcial]
- Modos de permissão [5]: tabela oficial — "default: Reads only"; "acceptEdits: Reads, file edits, and common filesystem commands (mkdir, touch, mv, cp, etc.)"; "plan: Reads, plus classifier-approved commands when auto mode is available"; "auto: Everything, with background safety checks"; "dontAsk: File reads inside your working directories and pre-approved tools"; "bypassPermissions: Everything — Isolated containers and VMs only". Trocar no CLI: "press Shift+Tab to cycle permission modes"; a barra mostra "⏸ manual mode on", "accept edits on", "plan mode on" [5]. Nenhum modo aprova sozinho remoções "rm/rmdir" de caminhos críticos [5]. [CONFIRMADO]
- CLAUDE.md [9]: "Run /init to generate a starting CLAUDE.md automatically"; confirmar carregamento com "/context all" (lista "Memory files"); "CLAUDE.local.md" para preferências privadas; importar arquivos com "@caminho". Auto memória carrega "first 200 lines or 25KB". [CONFIRMADO]
- Checkpoints [11]: "/rewind" (alias "/undo") ou Esc duas vezes com o campo vazio; guarda os 100 checkpoints mais recentes; snapshots apagados ~30 dias depois; limitação: "A file that only Bash commands changed isn't tracked and stays as it is. To revert it, use version control, such as Git." [CONFIRMADO]
- Verificação embutida [10]: "/code-review reviews the diff in a fresh subagent that never saw your conversation"; "/verify" para rodar e olhar o resultado; "/goal" com condição verificada a cada turno. [CONFIRMADO]
- Desktop: sessões paralelas, editor e terminal integrados, revisão visual de diff [3, índice]. Web: sessões na nuvem a partir de repositório GitHub [3, índice]. Detalhes não lidos. [VERIFICAR]

7. BOAS PRÁTICAS E EXEMPLOS DE PROMPTS
7.1 Publicadas pela Anthropic (Claude Code) [10][9]
- "Only write down what Claude can't find by reading the repo, or what it would otherwise spend time rediscovering every session." [10]
- "If you name the file, describe the symptom, and say what 'fixed' looks like up front, you usually save yourself a round of corrections later." [10]
- "Give Claude something it can run that comes back pass or fail. Once it has that, it can keep going on its own and you don't have to watch." [10]
- "Whichever option you use, ask Claude for evidence: the command it ran and its output... 'All tests pass' on its own tells you very little" [10].
- "One phrase that does still help is be ambitious" (quando se quer o escopo completo) [10].
- "If your repo already has one of these, the single most useful line in your CLAUDE.md is the command that runs it." [10]

9.1 Estudos independentes adicionais (segunda rodada; números copiados dos PDFs)
- ERROS SILENCIOSOS — "Fail Loudly: An Auditable Runtime for Agentic Data Analysis" (preprint 2026, pesquisadores independentes) [56]: define erro silencioso como "computations execute successfully but produce plausible yet incorrect outputs that fail to answer the intended question". Auditoria: "Among 580 zero-scored DS-STAR runs across KramaBench, DA-Code, and DABStep, 405 (69.8%) delivered normal-looking but incorrect results without reporting failure". Exemplo do artigo: pedido para pôr dois rankings Top-5 lado a lado, o agente juntou as tabelas "without a pairing condition". [CONFIRMADO; preprint sem revisão por pares — VERIFICAR status] Uso didático [SUGESTÃO]: é o melhor argumento para o aluno nunca aceitar "o script rodou" como prova de acerto.
- KramaBench (MIT e colaboradores; ICLR 2026) [55]: 104 desafios, 1.700 arquivos, 24 fontes, 6 domínios; "the best system reaches only 55% end-to-end accuracy in the full data-lake setting. Even with perfect retrieval, the accuracy tops out at 62%. Leading LLMs can identify up to 42% of important data tasks but can only fully implement 20% of individual data tasks" (versão v3). Versões anteriores e resumos de busca citam 50% e 59%: números mudaram entre versões. [CONFIRMADO v3]
- DA-Code (EMNLP 2024) [54]: 500 tarefas de manipulação de dados, aprendizado de máquina e análise exploratória com dados reais em ambiente executável; "using the current best LLMs achieves only 30.5% accuracy". [CONFIRMADO]
- InfiAgent-DABench (ICML 2024) [53]: 257 perguntas de análise sobre 52 arquivos CSV, 34 LLMs avaliados; perguntas abertas convertidas em formato fechado para correção automática. [CONFIRMADO] (Útil como modelo de exercício com resposta verificável.)
- DSBench (2024/2025) [37]: "466 data analysis tasks and 74 data modeling tasks, sourced from ModelOff and Kaggle"; "the best agent solving only 34.12% of data analysis tasks". [CONFIRMADO no PDF]
- DSDBench (EMNLP 2025) [57]: 1.117 amostras de código de ciência de dados com erros injetados (vários erros ao mesmo tempo, que se propagam por várias linhas); conclusão: "even frontier models that excel at code generation fail to reliably trace and resolve these errors, exposing a critical 'generation versus understanding' gap". O benchmark mira "non-expert, data-centric scripting" — exatamente o público do curso. [CONFIRMADO]
- PACOTES INEXISTENTES — Spracklen et al. (USENIX Security 2025) [39]: "2.23 million packages... of which 440,445 (19.7%) were determined to be hallucinations, including 205,474 unique non-existent packages"; média "at least 5.2% for commercial models and 21.7% for open-source models". [CONFIRMADO no PDF — substitui o VERIFICAR anterior] Reavaliação com cinco modelos de fronteira de 2026 (v4, nov/2026; pesquisador independente) [52]: "Hallucination rates are 3.6–5.0% of package mentions (2.2–3.4% of generations)"; "Python exceeds JavaScript for every model"; "at least 23 package names that the models suggest had previously hosted malware"; "one hallucinated name was registered with malware after our runs". [CONFIRMADO; preprint] [SUGESTÃO didática] Regra para o aluno: antes de aprovar "pip install"/"uv add" de um pacote desconhecido, conferir se ele existe no pypi.org e se é o pacote famoso que se esperava.
- PRODUTIVIDADE — METR (ensaio randomizado, 16 desenvolvedores experientes, 246 tarefas, fev–jun/2025) [58]: "developers forecast that allowing AI will reduce completion time by 24%. After completing the study, developers estimate that allowing AI reduced completion time by 20%. Surprisingly, we find that allowing AI actually increases completion time by 19%". Os autores alertam para não generalizar (programadores experientes em projetos que conhecem bem). [CONFIRMADO] [SUGESTÃO] Lição: a sensação de ganho não substitui medir; vale também para conferir resultados.
- REPRODUTIBILIDADE DE NOTEBOOKS — Pimentel et al. (Empirical Software Engineering, 2021) [61]: "Out of 863,878 attempted executions of valid notebooks... only 24.11% executed without errors, and only 4.03% produced the same results"; causas: dependências não declaradas, "hidden states, out-of-order cells, hard-coded paths". Entre repositórios que declaram dependências, 79,85% usam requirements.txt. [CONFIRMADO] [SUGESTÃO] Argumento central para o módulo de reprodutibilidade: notebook que só roda "na máquina de quem fez" não é análise reprodutível.
- Panoramas acadêmicos (surveys, 2025) de agentes de ciência de dados: Wang et al., arXiv 2508.02744 (v2 nov/2025) [59]; Rahman et al., arXiv 2510.04023 (out/2025; mapeia 45 sistemas em seis etapas do ciclo de vida e discute confiança e segurança em domínios críticos) [60]. Para a ementa (estado da arte). [CONFIRMADO resumos; leitura integral não feita]
